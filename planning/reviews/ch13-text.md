2. `docs/chapter13_rlhf/imitation-learning-pipeline.md` (and `docs/chapter13_rlhf/review.md`, key-equation reading) — "**only differences are identified**: adding the same constant to $r_\phi(x, y_w)$ and $r_\phi(x, y_l)$ leaves every preference probability unchanged, so the absolute reward scale is arbitrary and must be calibrated before PPO" — the inference is wrong: adding a constant changes the **offset** (location), not the **scale**. Under the Bradley–Terry likelihood $P(y_w \succ y_l \mid x)=\sigma(r_w-r_l)$: (a) $r_w,r_l \mapsto r_w+c, r_l+c$ leaves $\Delta r$ and therefore every probability unchanged ⇒ the _offset_ is unidentified; (b) $r_w,r_l \mapsto k r_w, k r_l$ gives $P=\sigma(k\Delta r)\neq\sigma(\Delta r)$ — e.g. with $\Delta r=1.5$, $\sigma(1.5)=0.8176$ but $\sigma(3.0)=0.9526$ — so the likelihood _does_ change ⇒ the multiplicative scale **is** identified (pinned by the sigmoid's unit temperature). "Only differences are identified" therefore says nothing about the scale being arbitrary. The neighbouring sentence "**only the ordering is constrained**" understates BT as well: a pair with $\Delta r=0.5$ still incurs loss $-\log\sigma(0.5)=0.474$ and is pushed to widen, so the margin encodes a calibrated probability, not just an ordering. The practical advice (calibrate the RM output scale before PPO, because the reward-to-KL ratio depends on it — see 13.4 "Reward Scale: Calibrate Before PPO") is sound, but the stated reason is not, and `review.md` repeats the same false claim ("only differences are identified, so the absolute scale must be calibrated before PPO"). — Suggested fix: "Only differences are identified, so the reward **offset** is arbitrary; the scale is pinned by the sigmoid's unit temperature, but it still has to be calibrated before PPO because PPO's reward-to-KL balance depends on it (Section 13.4)." Apply the same wording in `review.md`.

Fix the sidebar registration, the BT identifiability sentence, the two reward formulas, the "cannot be hacked" claim and the stale chapter references, and this revision is in good shape.
