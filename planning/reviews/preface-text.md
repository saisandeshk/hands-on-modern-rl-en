## Errors

1. `docs/preface/brief-history/index.md` — "**DeepSeek has the highest transparency**—it publicly disclosed that the V3 pre-training used about 2.788M H800 GPU hours." — **Wrong number, and a regression.** The DeepSeek-V3 technical report (arXiv:2412.19437, §4.2) splits the cost as: pre-training **2,664K** H800 hours, context-length extension 119K, post-training 5K, **total 2,788K** H800 hours. The check `2664 + 119 + 5 = 2788` reproduces the total exactly. So 2.788M is the *whole* training cost (pre-training **plus** extension **plus** post-training), not the pre-training figure. The number the writer deleted (2.664M) was the correct pre-training figure, and the book's own Appendix C says so: `docs/appendix_c_resources/gpu-hours-estimation.md` line 24 ("DeepSeek-V3 | 671B-A37B | 14.8T | H800-80G | **2,664,000**"), line 111 ("DeepSeek-V3 Pretraining | 14.8T tokens / **2.664M H800 hours**"), and `docs/appendix_c_resources/learning-resources.md` line 127 ("2.664M H800 hours training 14.8T tokens"). The same appendix prices the *total* at $5.576M = 2,788,000 × $2/h, which confirms that 2.788M is the all-in figure. The revision therefore contradicts two other pages of this book and mislabels a total as a pre-training cost. — Suggested fix: restore "the V3 pre-training used about 2.664M H800 GPU hours (2.788M H800 hours for the full training pipeline, including context extension and post-training)".

2. `docs/preface/env-setup.md` — "Install the lock file once for the full course, or install a single chapter file when you only want that chapter's dependencies." and "the following steps install the full pinned environment, which covers the experiments in Chapters 1-9 and the LLM post-training chapters out of the box." — **False.** `code/requirements.lock.txt` is missing packages that the course code actually imports: `matplotlib` (imported by `code/chapter01_cartpole/plot_curves.py`, `code/chapter05_dqn/dqn_cartpole.py`, `code/chapter06_policy_gradient/reinforce_cartpole.py`, `code/chapter08_ppo/ppo_from_scratch.py`, `code/chapter12_exploration_marl_hierarchical/multi_agent_marl.py`, `code/chapter19_agentic/tool_use_agent.py`, `code/chapter23_vlm/vlm_grpo_train.py`), `swanlab` (`code/chapter01_cartpole/1-ppo_cartpole.py`, `2-pytorch_ppo.py`, `code/chapter05_dqn/dqn_atari_sb3.py`), `ale_py` (`code/chapter05_dqn/dqn_atari_sb3.py`, `render_atari.py`), `opencv-python`/`pyboy` (Chapter 5), `modelscope` (Chapter 14 requirement file), `json5`/`openai` (Chapter 19 requirement file). The repo's own virtualenv shows the gap: `importlib.metadata.version("swanlab")` and `("ale-py")` both raise *PackageNotFoundError*, i.e. the repository's own `.venv` cannot run the Chapter 1 or Chapter 5 scripts. A reader who follows the page hits `ModuleNotFoundError: No module named 'swanlab'` on the very first chapter. — Suggested fix: either add the missing packages to `code/requirements.lock.txt`, or say explicitly that the lock file covers only the core stack and that the per-chapter files (and `code/requirements.txt`) must be installed on top of it.

3. `docs/preface/env-setup.md` — the "Global Verification Script" checks `for pkg in ["numpy", "matplotlib", "scipy", "tqdm"]` and promises "If all outputs show 'OK', the environment setup is complete." — **Cannot pass after following the page's own instructions.** Neither `matplotlib` nor `scipy` is in `code/requirements.lock.txt` (the lock has numpy 2.5.4, tqdm 4.70.1, but no matplotlib/scipy), and `scipy` appears in no requirements file in the repository at all. A reader who installs the lock file and runs the script gets `MISSING` for matplotlib and scipy. — Suggested fix: add `matplotlib` and `scipy` to the lock file (or drop `scipy` from the check and install `matplotlib` explicitly).

4. `docs/preface/env-setup.md` — "If you prefer conda or plain venv, any Python 3.12 environment works; install the same lock file with `pip install -r code/requirements.lock.txt`." — **The lock file cannot be installed on macOS or Windows.** It is a Linux/CUDA resolution: it pins `nvidia-cublas==13.1.1.3`, `nvidia-cudnn-cu13==9.24.0.43`, `nvidia-cusparselt-cu13`, `cuda-toolkit==13.0.3.0`, `nvidia-nccl-cu13` and `triton==3.8.0`, none of which publish macOS/Windows wheels, so pip fails with "Could not find a version that satisfies the requirement nvidia-cublas==…". This contradicts the same book's claim that the course runs on "Windows (WSL2)" and "macOS (Apple Silicon M1/M2/M3/M4 and Intel Macs)" (`docs/preface/introduction.md`, "Environment and Hardware Requirements"). It also contradicts the page's own "No GPU? You can still run the course" tip: a CPU-only user downloads the whole multi-GB CUDA 13 stack, and the page never mentions a CPU-only lock file or `--index-url` for the CPU wheel. — Suggested fix: publish a CPU/macOS-friendly requirements set (e.g. `code/requirements-cpu.txt`), or state that the lock file is Linux+CUDA only and give macOS/Windows readers the per-chapter route.

## Doubts

1. `docs/preface/brief-history/index.md` — "**2013**, DeepMind introduced the Deep Q-Network (DQN) … enabling an agent to learn control policies directly from screen pixels and reach human-level scores on many Atari arcade games (extended to dozens of games in the 2015 Nature version)." — The 2013 NIPS-workshop paper (`arXiv:1312.5602`) evaluated 7 games and beat the human baseline on 3 of them; the 49-game / human-level-on-43 result is the 2015 Nature paper. "many Atari arcade games" attached to 2013 is still an overstatement; consider "reach human-level scores on some of the Atari games it evaluated (49 games in the 2015 Nature version)".

2. `docs/preface/brief-history/index.md` — the GRPO objective is displayed with a **sequence-level** ratio `π_θ(o_i|q)/π_{θ_old}(o_i|q)`, and the new parenthetical only mentions the KL term ("simplified here; the full GRPO objective adds a KL penalty against a reference policy"). The book's own Chapter 15 states the opposite of what the formula shows: "Each token has its own ratio. GRPO clips those ratios independently … This is the original definition in DeepSeekMath Equation (3)" and reserves the sequence-level ratio for GSPO (`docs/chapter15_grpo/grpo-family.md`). A reader comparing the preface with Chapter 15 sees the preface present GSPO-style ratios as "GRPO". Consider dropping only the KL/length-normalization terms and keeping the token-level ratio, or labelling the ratio explicitly as sequence-level.

3. `docs/preface/brief-history/index.md` — the body says Anthropic published "Natural Emergent Misalignment from Reward Hacking" (arXiv:2511.18397, November 2025) while reference [^19] gives the title as "Emergent Misalignment: Researching the impact of reward hacking" (the June 2025 blog post). The arXiv ID and the November 2025 date cannot be checked offline; please align the two titles and re-verify the ID. The same applies to the other unverified IDs the report lists (UI-TARS-2 `2509.02544`, RPT `2506.08007`, GLM-4.5 `2508.06471`, Kimi K2 `2507.20534`).

4. `docs/preface/brief-history/index.md` — "**Step3-VL by Starry Sky** proposes PaCoRe parallel coordinated reasoning". Step3-VL is from StepFun (阶跃星辰), not "Starry Sky"; please use the official lab name. The "PaCoRe" method name also could not be verified offline.

5. `docs/preface/brief-history/index.md` — the writer's report justifies deleting "R1-Zero used 128K GPU hours" by saying "the R1 paper does not publish an equivalent headline number", but `docs/appendix_c_resources/gpu-hours-estimation.md` lines 113-114 cite the DeepSeek-R1 tech report for "~128K H800 hours (RL on V3 base)" and "~80K H800 hours" for R1-Zero specifically. The deletion is defensible (the original sentence attributed 128K to R1-Zero, which per Appendix C is R1's figure), but the rationale in the report is wrong.

6. `docs/preface/env-setup.md` — "## Minimal Working Setup (Get Running in 5 Minutes)" now describes installing the full pinned environment, i.e. torch 2.14.1 plus the CUDA 13 wheel stack; that is no longer a five-minute setup on a normal connection. Either keep a genuinely minimal path (gymnasium + torch CPU only) under that heading or rename it.

7. `docs/preface/env-setup.md` — the smoke-test command `.venv/bin/pytest code -q` is POSIX-only, while the same page teaches Windows activation (`.venv\Scripts\activate`). Consider `.venv/bin/pytest code -q  # Windows: .venv\Scripts\pytest code -q`. (The command itself is correct: `code/chapter03_value_functions/test_gridworld_q_learning.py` is the only test file under `code/`, it imports only the standard library, and `pytest==9.1.1` is in the lock file.)

8. `docs/preface/introduction.md` — "From Q-Learning to DQN, from PPO to DPO and GRPO, each evolution of reinforcement learning has pushed outward the boundary of what AI can do." — DPO is not an evolution of PPO (it is an offline, reward-model-free alternative to RLHF); the same page correctly avoids this elsewhere by removing DPO from the Model-Free list. "from PPO to DPO and GRPO" is at best loose.

9. `docs/preface/brief-history/index.md` — "DQN, which for the first time seamlessly integrated deep neural networks with reinforcement learning" — historically too strong (e.g. Zhang et al. 1995 DNQ, Riedmiller et al. 2005 R-network, Lu et al. 2008); "the first to reach human-level performance with deep RL from pixels" is the defensible claim. Pre-existing wording, but the writer edited this sentence.

10. `planning/content-review-notes.md` — the "Cross-references and numbering" entry still lists `preface/introduction.md` ("Chapters 8–9", "Chapter 8") as unfixed, and none of this pass's factual fixes (10^170 → 10^172, the DeepSeek-V3 figure, the Sutton & Barto 1998/2018 reference) are recorded there, as the repository guidelines require ("When fixing a factual error, record it (and the fix) in planning/content-review-notes.md"). The reference in the history page should also be marked `[x]`.

## Verdict

The pass is mostly careful and improves the text: the Go board-state exponent is now right (361·log10 3 = 172.24, so 3^361 ≈ 1.7×10^172), the AlphaGo/AlphaGo Zero distinction is correct, the Sutton & Barto reference is fixed, the DQN/2015-Nature wording is more accurate, and the chapter cross-references now match the sidebar (13-14, 19-22, and the Part II-IV mermaid relabelling are all correct and verified against `docs/.vitepress/config.mjs`). The serious problem is that the environment page was rewritten around `code/requirements.lock.txt` without checking what that lock file actually contains: the lock omits matplotlib, scipy, swanlab, ale-py, modelscope, json5 and openai, so "install the lock file once for the full course" and "covers the experiments in Chapters 1-9 … out of the box" are false, the page's own verification script cannot pass, and the lock is a Linux/CUDA-only resolution that breaks the advertised macOS/Windows and CPU-only setups. The package table's chapter column and the "per chapter" claim are also wrong (PyBullet, Isaac Lab, ML-Agents, LoRA and 11 missing chapter directories). Finally, the one numeric fix in the history page, the DeepSeek-V3 GPU-hour figure, is a regression: 2.788M H800 hours is the total (2,664K pre-training + 119K context extension + 5K post-training), it contradicts Appendix C, and the correct 2.664M pre-training figure was deleted. Six errors, ten doubts; the environment page needs another pass against the lock file before it is published.
