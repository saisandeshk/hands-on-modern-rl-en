# Review of ch25-lab

Independent re-derivation and re-execution of the Chapter 25 lab (`w/ch25-lab`).
All numbers below were reproduced by running the branch's own code with the project
`.venv` (numpy 2.5.4, Python 3.12.13); value-iteration numbers were computed with an
independent solver written for this review.

## Errors

1. `code/chapter25_alignment_failures/gridworld.py` — `evaluate_greedy` rebuilds the environment from the dataclass defaults (`env = LoopholeGridworld(reward_mode=reward_mode, max_steps=max_steps, **env_kwargs)`), so the evaluation environment always uses `bonus_reward=2.0`, `goal_reward=10.0`, `step_cost=0.05`, `dist_scale=0.5`, `gamma=0.99` no matter what the agent was trained with; neither `run_specification_gaming.run()` nor `run_eval_methodology.run_all()` forwards any of those. Measured consequences: (a) with `bonus_reward=0.2` the greedy farming rollout is reported as `eval proxy 57.00`, while the true return under the reward the agent was optimized is 30 x 0.2 - 60 x 0.05 = **3.00** (12.00 for b=0.5, 27.00 for b=1.0) — all three settings print 57.00; (b) with `--gamma 0.9` the fixed-mode row prints `eval proxy 14.275`, while the gamma=0.9 reward the agent was actually trained under gives **14.95** (`evaluate_greedy(..., gamma=0.9)` returns 14.95). This is exactly the knob Exercise 1 tells the reader to change, so the exercise reports proxy returns computed under a reward the agent never saw. — Suggested fix: pass the training environment's configuration into `evaluate_greedy` (accept the env object, or forward `bonus_reward`, `goal_reward`, `step_cost`, `dist_scale`, `gamma` from both callers).

2. `docs/chapter25_alignment_failures/lab.md` — "Part 2 defaults: 12 seeds per config, 400 training episodes, slip 0.1, seed 0 (about 3 minutes on CPU)" — measured on this machine the full Part 2 run takes **~1.2 s** (24 trainings x 400 episodes + 2000 bootstrap resamples), Part 1 takes **~0.6 s**, i.e. the whole lab is ~2 s, two orders of magnitude below the claim. `code/chapter25_alignment_failures/README.md` repeats it ("Part 1 full run ~10 s; Part 2 full run (24 trainings of 400 episodes + 2000 bootstrap resamples) ~2-4 min"), while the writer's own report says "Full-run wall time ≈ 12 s total on CPU (both scripts)" — three mutually inconsistent runtime claims, all far above the measured time. — Suggested fix: state "a couple of seconds" on the page, in the README, and in the report (or measure on the machine of record and quote that).

3. `docs/chapter25_alignment_failures/lab.md` — "The farming policy is optimal for the proxy MDP: with discount 0.99, collecting +2 every two steps near the start forever is worth far more than a one-time +10 minus travel costs" — the first clause is false for the environment as implemented, because the episode truncates after 60 steps and reaching the goal ends it. Exact value iteration over the (position, step) state space with the env's own reward gives V\*(start) = **46.52** for the _hybrid_ policy (farm the tile 28 times, then walk to the goal on the last step) versus **43.25** for pure farming and **11.22** for walking straight to the goal. In closed form: pure farming = (2.0 - 0.05 + 0.99(-0.05)) \* sum\_{k=0..29} 0.99^{2k} = 1.9005 x 22.754 = 43.25; the hybrid (28 farming cycles, then 5 steps to the goal) = 46.52; walking straight to the goal = 11.22. The optimum is therefore "farm first, collect the goal payout at the end", not "farm forever", and the learned pure-farming policy is not optimal. — Suggested fix: keep the qualitative point (the loophole makes farming worth 43.2 vs 11.2 discounted) but drop "is optimal", or state the hybrid explicitly.

4. `code/chapter25_alignment_failures/gridworld.py` and `docs/chapter25_alignment_failures/lab.md` — "Because the added term has the potential-based form, the set of optimal policies is unchanged -- the fix only densifies the learning signal" — the code applies the shaping only on non-terminal transitions (`if self.reward_mode == "fixed" and not done:`), so the implemented reward is not r + F on every transition and Ng et al. (1999) does not apply verbatim. Derivation: with Phi(terminal)=0 the ideal PBRS return is G*ideal = sum_t r_t + (gamma-1) sum*{t=1..T-1} Phi(s*t) - Phi(s_0); the implemented return is G_impl = G_ideal + Phi(s*{T-1}) = G*ideal - 0.5 \* d(s*{T-1}, goal), which is the constant -0.5 for every goal-reaching trajectory in this grid (all three predecessors of the goal are at distance 1) but is path-dependent (up to -3.0) for trajectories that end by truncation at step 60. Hence V*(s) = V*\_r(s) - Phi(s), and the optimal-policy invariance, does not hold for this reward; the claim as written is not justified by the code (in this environment the conclusion happens to survive: the greedy policy scores 14.275 vs ~-0.6 for the best truncating policy). The accompanying test does not check the environment either: `test_potential_shaping_preserves_optimal_policy` builds a separate 3-state MDP and adds the shaping to _all_ transitions with Phi(goal)=0, so it verifies the theorem, not the lab's reward function, while the page says it "checks exactly this". — Suggested fix: add the term on terminal transitions as well, using Phi(goal)=Phi(truncation)=0 (i.e. `reward += -self.potential(self._pos)` when `done`), and add a test that solves the env's own reward by exact value iteration and compares policies.

5. `docs/chapter25_alignment_failures/lab.md` (Exercise 1) — "Re-run Part 1 with `--alpha 0.25` fixed and bonus payouts of 0.2, 0.5, and 1.0 ... At which value does the greedy policy switch from farming to goal-seeking ... Hint: compute undiscounted returns for 'bounce on the bonus' vs. 'go straight to the goal' first" — the exercise has no answer as posed. Measured at the page's own setting (400 episodes, seed 0): b=0.2 gives a degenerate greedy policy (eval proxy -3.00, 0 bonus visits, 0% success — it neither farms nor reaches the goal; seeds 1-4 behave the same way, none reaches the goal within 400 episodes), b=0.5 and b=1.0 give a farming greedy policy (30 visits, 0% success). No tested value produces goal-seeking. The hinted threshold also does not match the agent's behaviour: undiscounted, pure farming overtakes the straight-to-goal path at b = 12.7/29 = 0.438; discounted (gamma=0.99, 60-step horizon) pure farming overtakes it only at b = 0.528; and the _optimal_ proxy policy (farm-then-go, see error 3) overtakes the straight-to-goal path already at b = 0.285 (b=0.29: hybrid 9.535 vs straight-to-goal 9.507). Three different thresholds, none of them the hinted 0.438. — Suggested fix: ask for the discounted comparison and mention the hybrid policy, choose bonus values that straddle b = 0.29, and note that with a small bonus the greedy policy needs far more than 400 episodes to find the goal.

6. `docs/chapter25_alignment_failures/lab.md` — heading/front-matter number "25.L Lab: Reward Hacking and Honest Evaluation" — the page is not listed in `docs/.vitepress/config.mjs` although AGENTS.md requires every new page to be added to the sidebar, so the lab is unreachable in the built site; and "25.L" cannot coexist with the repo's tooling: `scripts/fix-heading-numbers.mjs` parses sidebar entries with `/text:\s*'((?:[A-Z]\.)?\d+(?:\.\d+)*)\s+([^']+)'/`, which never matches "25.L". Worse, once the page is added as "25.6", the fixer matches only the numeric prefix "25" of the front-matter title and of the H1 and rewrites them into "25.6 .L Lab: ..." and "# 25.6.L Lab: ..." (its `numRe` strips only the digits). The new directory is also missing from the chapter-code index in `code/README.md`. — Suggested fix: number the page "25.6" in the front-matter title and the H1, add the sidebar entry, and add a row to `code/README.md`.

## Doubts

1. Part 1's headline greedy numbers are knife-edge in the training length. At the documented 400 episodes the greedy policy farms (eval proxy 57.00, 30 bonus visits/episode, 0% success), but the same configuration with `--episodes 800` gives eval proxy -3.00 (0 bonus visits), 1000 -> -1.00, 1200 -> -3.00, 1500 -> -1.00 (the 2-state loop the writer's report mentions). The page presents 57.00 as _the_ result of the lab with only "400 training episodes per reward mode, seed 0" as a caveat, while the writer's own report documents the instability. Either state the fragility on the page or pin the claim to the behavioural tail.

2. The page's selective-reporting table says "single seed (seed 0) | 1.000 | 1.000 | tie" and "best-3 seeds | 1.000 | 1.000 | tie: 'both perfect'", but the script prints "-> winner: A_stable" for both (`cherry_pick_report` breaks ties with `>=` and `max` over a dict). The page and the tool disagree about what the tool says.

3. The page credits `stratified_bootstrap_ci` with the difference interval ("`stratified_bootstrap_ci` resamples seeds _within_ each config ... including an interval for the IQM _difference_"); that function returns per-group intervals only — the difference interval comes from the separate `bootstrap_diff_ci`. "the only number that can license a claim like 'A beats B'" also overstates: a bootstrapped mean or median difference licenses the same claim.

4. Exercise 5 ("Rank by the training objective instead ... what kind of policy does that crown -- a better solver or a better farmer?") has a false premise for Part 2: Part 2 trains under the _repaired_ reward, where the bonus pays once, so the proxy is not hackable. Ranking by proxy gives the same winner (A) and the per-seed proxy values are monotone with success (A's three lowest proxy values, 0.87, 1.65 and 3.73, are exactly its three worst runs, with success 0.00, 0.07 and 0.28). The honest answer is "a better solver", not "a better farmer".

5. Exercise 3's hint ("bootstrap interval width shrinks roughly as 1/sqrt(n); predict the new width before running") predicts ~0.63 at 24 seeds; the measured interval is [+0.003, +0.489], width 0.486, and the conclusion flips by 0.003 — knife-edge, so "does the CI shrink enough to exclude zero?" lands on a boundary case that depends on the seed.

6. `stats.py::iqm_score` trims with `lo = n // 4`, `hi = n - n // 4`, which is exactly "the middle 50%" only when n is divisible by 4 (n=12 here, n=24 for Exercise 3); for n=10 it keeps 60% of the runs, while the docstring and the page both describe quartile trimming.

## Verdict

The lab is well built and unusually honest for a first draft: every number quoted on the page reproduces exactly (Part 1: 40.20 / 0.00 / 57.00 / 0.00 / 30.0 and 14.22 / 1.00 / 14.28 / 1.00; Part 2: mean 0.688 / 0.553, median 0.855 / 0.500, IQM 0.817 / 0.577 with CIs [0.450, 1.000] and [0.235, 0.877], difference +0.240 [-0.253, +0.642], best-3 1.000 vs 1.000, 4/12 aligned pairs disagreeing), the per-seed table matches the CSV, the IQM/median/mean arithmetic checks out by hand, the 9 pytest cases pass, the cross-references to 25.1.2/25.4.2/25.4.3/25.5.1 and the "four gauges" and CoastRunners attributions are faithful to the chapter, and the Ng et al. (1999) citation is genuine. The problems are in the claims built on top of those numbers: (1) `evaluate_greedy` silently evaluates under the default reward, which corrupts exactly the quantity Exercise 1 varies (and the `--gamma` path); (2) the potential-based-shaping invariance is claimed for a reward that omits the shaping on terminal transitions, and the accompanying unit test verifies a different MDP; (3) "the farming policy is optimal for the proxy MDP" is false — the optimum farms and then takes the goal at the last step (46.52 vs 43.25) — which also leaves Exercise 1 without a defensible threshold; (4) the runtime claims are off by two orders of magnitude and contradict the writer's own report; and (5) the page is unreachable in the site and its "25.L" number will be mangled by the repo's heading fixer. The substantive demonstrations (proxy-vs-utility divergence, robust statistics over 12 seeds, how selective reporting reverses a conclusion) all hold up; fixing the evaluation-configuration bug, the shaping invariance, and the optimality claim would make the lab trustworthy.
