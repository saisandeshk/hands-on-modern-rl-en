## Errors

1. `docs/chapter20_swe_agents/meta-swe-rl.md` — "**Algorithm**: GRPO + simple binary reward" / "The reward function in SWE-RL is extremely simple: `if all(test_results): return 1.0`" — this contradicts `docs/chapter20_swe_agents/swe-bench-and-rlvr.md:221,223`, which states the opposite about the same paper (arXiv:2502.18449): "The paper adopts a lightweight rule-based reward, for example comparing the similarity between the model's solution and the developer's real solution" and "the core reward of the SWE-RL paper cannot be simplified into 'score 1 if all hidden tests pass.'" The new `review.md:7` repeats only the first side ("the supplementary reading showed the SWE-RL recipe (GRPO plus a binary test reward)"). The contradiction pre-existed, but the revision rewrote the whole supplementary page around the binary-reward claim without reconciling the sibling page, so the chapter now states two incompatible things about one paper and the new summary page locks in the wrong half. — Suggested fix: pick the description that matches the paper (the paper's published reward is rule-based and combines the test signal with patch-similarity feedback) and state it identically on both pages; if the binary test reward is what later systems use, mark it as such ("the recipe the book follows: GRPO with a binary test reward, which is not the paper's full reward definition").

2. `docs/chapter20_swe_agents/meta-swe-rl.md` — "def swe_rl_reward(test_results): ... if all(test_results): return 1.0" — with an empty test list, `all([])` is `True` in Python, so a rollout in which no test was collected (collection error, empty suite, truncated run) receives the **maximum** reward. The revision fixed exactly this bug class in the sibling page (`swe-bench-and-rlvr.md`: "if len(test_results) == 0: return 0.0") and in `review.md` Exercise 7 (`swe_reward([]) → 0.0`), but left the copy on the page whose whole job is to show the reward function. A reward that pays full marks for an empty result set is a direct reward-hacking surface, and it also contradicts the chapter's own "Limits of the Test Signal" discussion. — Suggested fix: `if not test_results: return 0.0` before the `all(...)` check.

3. `docs/chapter20_swe_agents/meta-swe-rl.md` — "**Group-wise Normalization**: naturally handles tasks of varying difficulty (high variance in easy tasks, low variance in hard tasks)" — the parenthetical is inverted. GRPO's advantage is $(r_i - \mu)/\sigma$ over the group, so $\sigma$ is near zero exactly when the group is uniform: all rollouts succeed (easy task → all correct → zero variance) and all rollouts fail (hard task → all zero → zero variance). The variance is *largest* for tasks of intermediate difficulty. The page contradicts itself two sections later ("If a prompt's N rollouts all fail (reward is 0 for all), its intra-group variance is also 0") and `review.md` Exercise 3 states the correct version ("$\sigma = 0$ — the advantage is undefined"). — Suggested fix: "high variance for tasks of intermediate difficulty, near-zero variance for tasks that are already solved or still unsolved; that is why groups with no spread must be filtered out."

4. `docs/chapter20_swe_agents/meta-swe-rl.md` — "if max(rewards) > 0: # At least one success" followed by "This aligns with the idea of [DAPO's Dynamic Sampling] — discarding prompts whose rollouts carry no learning signal (all fail, or all succeed trivially)" — the code implements only the first half of what the sentence claims: a group whose rollouts all succeed has zero intra-group variance and is kept by this filter, although the prose says it is discarded. The revision added the "or all succeed trivially" clause without touching the code, and `review.md` Exercise 8 defines a *different* `filter_prompts` with the same name (`max(rs) > 0 and _variance(rs) > 0`). Two different semantics for one function name in the same chapter. — Suggested fix: make the snippet discard zero-variance groups as well (e.g. `if max(rewards) > 0 and len(set(rewards)) > 1`), and use the same rule in `review.md` Exercise 8.

5. `docs/chapter20_swe_agents/swe-bench-and-rlvr.md` — "**Rollout distillation** goes one step further: a stronger teacher (a larger model, a model with more tool steps, or the same model with test-time search) generates the successful trajectories, and the smaller student learns from them. When teacher and student share the same rollout distribution during training, this is called **on-policy distillation** (see [15.7 On-Policy Distillation](../chapter15_grpo/on-policy-distillation))" — this misdefines OPD relative to the page it links to. In ch15 §15.7 the defining property of OPD is that "the teacher does not rewrite the answer; instead, it reads every step written by the student and judges whether each token is reasonable": the *student* generates the trajectory and the teacher supplies token-level log-prob targets. Teacher-authored trajectories are exactly what ch15 calls SFT/SeqKD or off-policy distillation ("Who produces the training trajectory: teacher"). The new paragraph also introduces "rollout distillation", a term that appears nowhere else in the book and that duplicates ch15's off-policy distillation. — Suggested fix: define OPD as "the student generates the trajectory, the teacher provides token-level targets on it", and reserve "teacher writes the trajectories" for offline/SFT-style distillation; drop or cite the non-standard "rollout distillation" term.

6. `docs/chapter20_swe_agents/world-model-and-deep-swe.md` — "CWM's world model makes MCTS efficient" and "The entire MCTS is performed on the world model—**no real-world testing is needed**, making it extremely fast" — the revision gave the DeepSWE half of the page the "Teaching Alternative / needs its own ablation" treatment but left the CWM half asserting the opposite, so the page contradicts itself: the opening says CWM's "world model" is "primarily the execution regularities learned in the model weights, **not a separate transition model that has already replaced real tests**", and the CWM training box says "Reduce some real test calls" plus "Phase 3: Real Testing Fine-tuning … Correct the deviation between the world model and the real environment". 12. `docs/chapter20_swe_agents/review.md` (Exercise 2 solution) — "The optimal policy then prefers immediate submission of an unchanged patch ($R \approx 0 - 0.1 \times 1 = -0.1$, or 0 with no penalty on abort) over a genuine repair ($1.0 - 4.0 = -3.0$)" — with the exercise's own pass-fraction reward, the unchanged patch is not the optimum: a 1-step repair that passes 1 of 12 tests scores $1/12 - 0.1 = -0.0167 > -0.1$, and a 1-step repair passing 2 of 12 scores $2/12 - 0.1 = +0.0667 > 0$. The claim only holds for an all-or-nothing reward with no partial credit. The correct statement is that the step penalty of a necessary 40-step repair ($0.1 \times 40 = 4.0$) exceeds the maximum attainable test reward (1.0), so every long genuine repair is dominated and the policy degenerates toward short trajectories with whatever partial credit it can grab. — Suggested fix: restate the optimum as "short trajectories with partial credit beat genuine long repairs" and keep the "abort" case as one instance of that degenerate policy.

## Verdict

The revision is a net improvement: it removes the invented "Meta" attribution and the 80K/90K task table from the supplementary page, drops the fabricated DPO/PPO/GRPO ablation numbers and the mixed-split leaderboard, reframes the DeepSWE "training phases" box so it no longer presents teaching alternatives as the published recipe, expands the GAE formula to the correct full sum, fixes the undefined `done`/`tests_passed` in the SSR pseudocode, and adds genuinely useful coverage (verifier splits, sandbox contract, rollout plumbing, compute ledgers) that closes real gaps. All eight exercise solutions recompute correctly (9/12 = 0.75, shaped 0.57, GRPO advantages [1,1,−1,−1], δ₀ = 0.295, δ₁ = 0.5, Â₀ = 0.76525, 1,600 rollouts / 9.6M tokens / 533.3 min / 66.7 min, and all coded outputs match) — the only defect there is the Exercise 2 optimality claim. The most important problems are the ones the rewrite created or left in place: (i) the chapter now states two incompatible descriptions of the SWE-RL paper's reward, and the new summary page repeats only one of them; (ii) the new distillation paragraph misdefines on-policy distillation relative to the ch15 page it links to; (iii) the new binary reward function still pays the maximum reward for an empty test list, the exact bug the same revision fixed elsewhere; (iv) the GRPO variance claim is inverted and contradicts the page's own filtering section; (v) the CWM MCTS and DeepSWE beam-search sections were left asserting (respectively) that no real testing is needed and that DeepSWE uses a value model, both of which the revision's own reframing denies; and (vi) the new `review.md` is not in the sidebar, so it is unreachable and will be dropped from the EPUB/PDF, and its "20.R" number breaks the book's section-numbering convention. The de-fabrication is also incomplete: `appendix_c_resources/learning-resources.md` still attributes both papers to Meta. The pattern is good but the writer must reconcile the pages against each other rather than only against the "original draft", and must finish the sidebar/appendix bookkeeping.
