## Errors

1. `docs/chapter08_ppo/ppo-math.md` (line 280, new text) — "In the $A_t > 0$ case `torch.min` lets surr1 dominate inside the safe interval and lets the clipped term dominate outside it." — This is wrong for the region below the lower bound, and it contradicts the table immediately above it. With $A_t=2$, $r_t=0.7$: surr1 $=0.7\times2=1.4$, surr2 $=\text{clip}(0.7,0.8,1.2)\times2=1.6$, so $\min=1.4=$ **surr1**, not surr2 (the writer's own table row says "surr1 / Below the lower bound, optimize normally"). `min` picks the _clipped_ term only in the same-direction overshoot region ($A_t>0$ with $r_t>1+\varepsilon$, $A_t<0$ with $r_t<1-\varepsilon$); the min-selection rule is **symmetric** in the two signs, and what differs is _which_ bound is the same-direction one. The added sentence "In the $A_t < 0$ case the picture is asymmetric" therefore mis-describes the structure it is trying to fix. — Suggested fix: "In the $A_t>0$ case `torch.min` picks the clipped term only above $1+\varepsilon$ (same-direction stop, gradient zero); below $1-\varepsilon$ it picks the unclipped term, whose nonzero gradient pulls the ratio back up. The $A_t<0$ case is the mirror image: the clipped term wins below $1-\varepsilon$, the unclipped term above $1+\varepsilon$."

2. `docs/chapter08_ppo/ppo-math.md` (lines 257, 282) and `docs/chapter08_ppo/trust-region-clipping.md` (line 372) — residual statements that the corrected analysis now contradicts: "**Gradient control**: when the ratio leaves the clipping interval, the clipped term becomes a constant, `min` picks the clipped term, and the gradient automatically drops to zero"; "inside the safe interval it equals surr1 (the original objective), and outside it equals surr2 (the clipped constant)"; "once the policy ratio leaves the safe interval, the gradient automatically vanishes". All three are false in the opposite-direction overshoot region ($A_t<0,\ r_t>1+\varepsilon$ ⇒ $\min$ picks surr1 $=\!-3.30$, gradient non-zero). `trust-region-clipping.md` contradicts itself: its own four-case table (lines 267–272) says "unclipped value / nonzero, decrease $r_t$" for $A_t<0,\ r_t>1+\varepsilon$. Since the writer fixed exactly this point in the table above, the contradicting sentences should have been fixed in the same pass. — Suggested fix: qualify each sentence with "in the same-direction overshoot region" and point at the four-case table.

3. `docs/chapter08_ppo/rl-long-horizon-planning.md` (line 176) — "the accumulated error after $k$ steps is roughly $O(\epsilon \cdot \frac{\gamma^k}{1-\gamma})$" — the expression _decreases_ with $k$ ($\gamma^k\to0$), which directly contradicts the sentence before it ("short-horizon predictions are accurate enough, while long-horizon prediction errors accumulate too fast"). The accumulated model error must grow with the rollout length and saturate, e.g. $\epsilon\cdot\frac{1-\gamma^k}{1-\gamma}$ (the geometric sum $\sum_{i<k}\gamma^i$); this is exactly why MBPO uses $k\approx5$. The writer flagged this bound as "suspicious" in the report and then left it in the page. — Suggested fix: replace $\gamma^k$ by $1-\gamma^k$ (and check the constant against Janner et al. 2019, Theorem 3, before finalising).

4. `docs/chapter08_ppo/rl-long-horizon-planning.md` (lines 258–263, writer-added lead-in) — "Concretely, the world model trained in Stage 1 has three learned parts: … 3. **Policy model**: learns the policy in latent space, $\pi(a|z_{1:t})$" — the policy model is _not_ part of the world model and is _not_ trained in Stage 1; the page's own Stage 2 says "The world model is frozen… an Actor-Critic is trained on these imagined sequences". ## Doubts

1. `docs/chapter08_ppo/ppo-math.md` (line 513, new "Advantage Normalization" subsection) — "Almost every PPO implementation therefore standardizes the advantages once per rollout" and "normalize once over the whole rollout batch, not separately inside each minibatch". The advice matches the chapter's own `snippets/ppo-code-map.py` (batch-level normalization) and modern LLM-RL stacks (TRL/veRL/CleanRL), but it is stated as a fact about "almost every" implementation: Stable-Baselines3's `PPO` has `normalize_advantage: bool = False` by default — and SB3 is the implementation used for the §8.1 experiment — while OpenAI baselines' PPO2 normalizes _per minibatch_, i.e. exactly what the text calls wrong. Not clearly wrong as best practice, but too absolute; consider "a common practice (and what this chapter's code does)" plus a note that per-minibatch normalization is the classic baselines behaviour.

2. `docs/chapter08_ppo/rl-long-horizon-planning.md` (line 455) — "Later work such as DAC (Discriminator-Actor-Critic) and AIRL … improved the stability of GAIL". The expansion is now correct, but DAC (Kostrikov et al., 2018/ICLR 2019) is a recurrent _off-policy RL_ algorithm that reuses GAIL's discriminator to provide an intrinsic exploration reward; it is not a "GAIL stability" improvement. AIRL (Fu et al., 2018) is the work that actually addresses GAIL's reward-hacking/instability via a state-only reward. Consider rewording as "built on GAIL's discriminator".

3. `docs/chapter08_ppo/rl-long-horizon-planning.md` (line 440) — "the error compounding drops from the quadratic-in-$T$ blowup of plain BC … to near-linear in $T$". The no-regret/DAgger statement is now correct, but the page's own BC paragraph (line 427) describes the compounding error as "proportional to the horizon" ($1-(1-\epsilon)^T\approx T\epsilon$), i.e. linear; the quadratic refers to the _expected cost_ $\approx\epsilon T^2/2$, a different quantity. Also, DAgger's bound is $O(T)$, so "near-linear" is looser than the theorem. Suggest naming the quantity (expected imitation cost) explicitly.

4. `docs/chapter08_ppo/ppo-bipedal-walker.md` (line 306, new text) — the new paragraph correctly states that "SB3 learns $\sigma$ as a separate parameter vector (one per action dimension, shared across states)", but the formula two lines above still writes $\mathcal{N}(\mu_\theta(s), \sigma_\theta(s)^2)$ and the sentence above it says "the policy network outputs the Gaussian distribution, with mean $\mu(s)$ and standard deviation $\sigma(s)$" — i.e. state-dependent, which is not SB3's default (`use_expln=False` ⇒ one `log_std` vector for all states). Not wrong per se (SB3 does support `use_expln=True`), but the notation and the new sentence should be reconciled, e.g. write $\sigma_\theta$ (state-independent) for the SB3 default.

5. `docs/chapter08_ppo/ppo-bipedal-walker.md` (lines 218–233) — the added `Standard deviation: 12.6` line makes code and sample output agree, but the underlying run cannot be reproduced offline (no gymnasium/BipedalWalker here). With mean $-103.7$, std $12.6$, best $-77.8$ and worst $-124.7$ the four numbers are mutually consistent (range $\approx3.7\sigma$ over 50 episodes), so this looks plausible; flagged only because the page presents it as "the result of one run" with no seed.

## Verdict

The revision is solid in the parts it re-derived: the GAE numbers (I reproduced `[0.7611 0.7051 0.6465 0.4801 0.2]` / returns `[0.8611 0.9051 0.9465 0.9801 1.0]` and the $\lambda=0$ TD column `[0.098, 0.097, 0.195, 0.292, 0.2]` exactly), the $\pm23.3$ advantages, the KL value $1.175\approx1.18$, and all eight exercises of the new `review.md` (Exercises 5, 7 and 8 executed; the torch assertions hold at $10^{-6}$). The paper-attribution fixes (GAE 2015/2016, DAC, DreamerV3 Nature 2025, PPG) are correct. The most serious problems are that the _new_ summary sentence added to `ppo-math.md` states the wrong `min` rule for $A_t>0$ below the lower bound (and calls the case "asymmetric" when the rule is symmetric), while three residual sentences on the same pages still claim the gradient always vanishes outside the interval; the MBPO accumulated-error bound on `rl-long-horizon-planning.md` still has $\gamma^k$ where it needs $1-\gamma^k$ (the writer noticed and left it); the new lead-in wrongly makes the policy model part of the Stage-1 world model; and the new `review.md` is an orphan page — not in the sidebar, with a "8.R" label the heading tool cannot parse, and a checkpoint harness that loads files the chapter's code never produces. The new "Advantage Normalization" subsection is good content but overstates a convention that SB3 (used in §8.1) does not follow by default. Beyond these, the fixed items were not marked `[x]` in `planning/content-review-notes.md` as the repo requires.
