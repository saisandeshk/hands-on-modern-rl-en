# Review of nt-4

## Errors

1. `docs/chapter24_multimodal_frontier/embodied-intelligence/model-based-rl/index.md` — "$\sum_{k=0}^{K_{\text{unroll}}}\left(\ell^r(u_{t+k}, r_k)+\cdots\right)$" together with "$r_{k+1},s_{k+1}=g_\theta(s_k,a_k)$" — the loss indexes the reward as $r_k$, but the dynamics function defined on the page only outputs $r_{k+1}$; at $k=0$ the term $r_0$ is never produced, and for $k\ge1$ the prediction $r_k$ belongs to the transition into $s_k$ while its target is written $u_{t+k}$. Either the decomposition should be $r_k,s_k=g_\theta(s_{k-1},a_{k-1})$ with a stated $k\ge1$ range, or the reward term should be $\ell^r(u_{t+k+1},r_{k+1})$. — Suggested fix: make the unroll indices agree, and state explicitly whether the $k=0$ root has a reward target.

2. `docs/chapter19_agentic/review.md` — "scores about 20 of 50 (39.0% as printed by the lab)" and "Gain $\approx 9$ percentage points" — $20/50=0.40=40.0\%$, and $39.0\%$ of $50$ is $19.5$ problems, which cannot occur with an integer count. A student who follows the problem statement gets $40.0-30.0=10$ percentage points, not 9. — Suggested fix: use a consistent pair, e.g. "20 of 50 = 40.0%, a 10-point gain", or "19 of 50 = 38.0%, an 8-point gain"; do not mix 39.0% with "about 20 of 50". (This predates nt-4, but the page is in scope and the branch did not fix it.)

3. `docs/appendix_b_algorithms/dapo.md` — "bad actions with negative advantage should move more cautiously (lower bound can be smaller)" — for $A<0$ the lower clip is active below ratio $1-\epsilon_{\text{low}}$; making $\epsilon_{\text{low}}$ _smaller_ lowers that threshold and lets the ratio fall further before clipping, i.e. a _larger_ downward update, not a more cautious one. Also the page itself uses $\epsilon_{\text{low}}=0.2$, not a value smaller than the symmetric 0.2; only $\epsilon_{\text{high}}$ is raised. — Suggested fix: say that a smaller lower bound permits stronger suppression of bad actions, or, if caution is intended, that the lower bound should be larger.

4. `docs/chapter22_computer_use/training.md` — "with horizon $T$ (maximum steps)" and "Consider a 50-step task $T=(s_0,a_1,s_1,\ldots,a_{50},s_{50})$" — the new definition makes $T$ the horizon, but the same page also uses $T$ for the task tuple. The same letter now denotes a scalar horizon and a trajectory object. — Suggested fix: rename the task tuple to $\tau$ or $\xi$ (or rename the horizon to $H$).

5. `docs/chapter22_computer_use/training.md` — "$r_{\text{progress}}(o_t,o_{t+1})$" versus the code immediately below, `def compute_progress_reward(s_t, s_{t+1}, task)` — the equation was changed to observations, but the code and its explanation still use $s_t,s_{t+1}$. The page also defines $\mathcal{S}=\{\text{screenshots}\}$, so the $o_t$/$s_t$ distinction is not established. — Suggested fix: either revert the equation to $r_{\text{progress}}(s_t,s_{t+1})$ or rename the code arguments and prose to $o_t,o_{t+1}$.

6. `docs/chapter24_multimodal_frontier/audio-reward-design.md` — "Here $r_t(\theta)$ is the new-to-old policy probability ratio" — on the same page $r$ already denotes the reasoning chain in $(r^{(i)},a^{(i)})\sim\pi_{\theta_t}$ (MGRD) and the scalar GRM output in $r=\phi(g)$; the change from $\rho_t(\theta)$ therefore gives $r$ three distinct meanings on one page. — Suggested fix: keep $\rho_t(\theta)$ on this page, or rename the reasoning trace and the GRM scalar (e.g. $z^{(i)}$ and $s$); the notation page allows both ratio symbols.

7. `docs/appendix_b_algorithms/dapo.md` — the "Four Modifications" table still writes "symmetric `clip(r, 1-ε, 1+ε)`" — after the Core Variables change, $r$ is the reward and the ratio is $r_t(\theta)$, so this table still uses the old bare-$r$ ratio that the prose change was meant to remove. — Suggested fix: write `clip(ratio, 1-eps, 1+eps)` or `clip(r_t(θ), 1-ε, 1+ε)` in the table.

## Doubts

1. `docs/chapter19_agentic/credit-assignment.md` — "$G^S(s)=\{(a_t^{(i)},G_t^{(i)})\mid s_t^{(i)}=s\}$" — the rename makes $G$ denote both the group/set ($G^S$, $G_k^H$) and the discounted return ($G_t$, $G(s_t)$) on the same page. The superscript/subscript distinguishes them, but the formulas now read as if a set and a scalar share a symbol. Using $\mathcal{G}^S$ for the group would remove the ambiguity.

2. `docs/chapter19_agentic/credit-assignment.md` — "$h_t=f_\phi(s_t,a_t)$" — $\phi$ is introduced here as the LLM encoder parameters, while the AgentPRM subsection a few paragraphs later uses $Q_\phi(s,a)$ with $\phi$ as the PRM parameters. The same symbol names two different networks on one page. The intended meaning is recoverable from context, but the page would be cleaner with a different subscript for the encoder.

3. `docs/chapter19_agentic/overview.md` and `docs/chapter19_agentic/review.md` — "$T$ is the horizon (number of steps)" with $\sum_{t=0}^{T}$ — if $T$ is the number of steps, indices $0,\ldots,T$ give $T+1$ terms. The convention may be "T is the final index", but the new parenthetical says otherwise. Either define $T$ as the final index or sum to $T-1$.

4. `docs/chapter22_computer_use/training.md` — "Define the Computer Use MDP as $\mathcal{M}=(\mathcal{S},\mathcal{A},P,R,\gamma,T)$" with "$\mathcal{S}=\{\text{screenshots}\}$" — the prose says a screenshot is only a partial state and the new progress equation uses observations $o_t$, but the formal object is an MDP whose state is the screenshot. This is either an MDP with full state equal to the screenshot or a POMDP with hidden application state; the page currently mixes the two. Making it a POMDP (state plus observation function) would match the "partial state" discussion.

5. `docs/chapter24_multimodal_frontier/review.md` — "$L^{CLIP}=-\mathbb{E}[\min(r_t(\theta)\hat A_t,\operatorname{clip}(r_t(\theta),\ldots)\hat A_t)]$" — the review now uses $r_t(\theta)$, but §24.4 defines and uses $\rho_t(\theta)$ for the same ratio; the notation page lists both, so this is not a mathematical error, but the chapter's body and summary no longer share one symbol. Consider either leaving the review at $\rho_t$ or updating §24.4 too.

6. `docs/chapter26_selfplay_frontiers/llm-multi-agent-rl/index.md` — the code comment "the per-role split of Section 26.3.2 (distinct R_i per role) is not implemented here" — the surrounding text and formulas were changed to lowercase $r_i$; the comment is a leftover. Minor, but it contradicts the new notation.

7. `docs/chapter24_multimodal_frontier/audio-reward-design.md` — "keeps questions with pass@8 between 3 and 6" — pass@k is normally a probability/rate in $[0,1]$ (the chance that at least one of $k$ samples is correct), not a count. If the intent is the number of successful samples out of eight, say "3 to 6 of 8 samples pass". The surrounding discussion of easy versus ambiguous questions is otherwise coherent.

## Verdict

The branch does most of what it claims: the renames to lowercase rewards, $G_t$ returns, $r_t(\theta)$ ratios, $\pi_{\text{old}}$, $y_t$ targets, and $r_\phi$ reward models are consistently applied in the main formulas, and the touched arithmetic examples (WebShop mean 0.58, $[0.81,0.9,1.0]$, ORM/PRM credits, group advantages) recompute correctly. The important problems are a genuine index mismatch in the MuZero loss, where $g$ outputs $r_{k+1}$ but the loss uses $r_k$ (so $r_0$ is undefined), a numeric inconsistency in the Chapter 19 exercise (39.0% versus 20/50), a backwards caution claim in the DAPO clipping discussion, and two notation collisions introduced by the changes: $T$ is both horizon and task in Chapter 22, and $r$ means ratio, reasoning trace, and scalar reward in the Chapter 24 audio page. The report's "notation consistency" claim is therefore overstated: the DAPO table and the Chapter 26 code comment still carry the old symbols, and the Chapter 24 review now uses $r_t(\theta)$ while §24.4 keeps $\rho_t(\theta)$. Fixing the MuZero indexing and the two collisions should be the priority.
