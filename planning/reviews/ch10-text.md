# Review of ch10-text

Scope reviewed: `docs/chapter10_offline_rl/offline-data-distribution-shift.md`, `docs/chapter10_offline_rl/sequence-modeling.md`, `docs/chapter10_offline_rl/experiments.md`, new `docs/chapter10_offline_rl/review.md`, plus `docs/.vitepress/config.mjs` and `planning/content-review-notes.md` (both supposed to be touched by this revision but are not in the diff). Base: `english-only...w/ch10-text` (4 doc files + report).

## Errors

1. `docs/chapter10_offline_rl/sequence-modeling.md` — "def act(self, state, target_rtg, history):" — the revision drops the `t` parameter from `act`, but the inference pseudocode on the same page (line 143) still calls `action = model.act(state, target_return, history, t)`. The snippet and the pseudocode are now mutually inconsistent and the pseudocode raises `TypeError: act() takes 4 positional arguments but 5 were given`. This is a regression introduced by the revision (the pre-revision `act` had the `t` parameter, so the call site matched). — Suggested fix: keep the call site as `model.act(state, target_return, history)` (and drop the now-unused `t` from the loop header, or keep the parameter and pass it), so the two code blocks agree.

2. `docs/chapter10_offline_rl/offline-data-distribution-shift.md` — "$\lambda = \frac{\alpha}{\frac{1}{N}\sum_i |Q(s_i, a_i)|}$" — the revision replaces the denominator $Q(s_i,\mu_{\theta_k}(s_i))$ (the current policy's action) with the *dataset* action $a_i$. This contradicts the cited source: Fujimoto & Gu 2021 (TD3+BC), Eq. (3)–(4), defines $\max_\theta \mathbb{E}_{(s,a)\sim\mathcal D}[\lambda Q_\phi(s,\mu_\theta(s)) - (\mu_\theta(s)-a)^2]$ with $\lambda = \alpha/(\frac1N\sum_i |Q_\phi(s_i,\mu_{\theta_k}(s_i))|)$, $\alpha=2.5$; the official implementation likewise uses `Q1(state, actor(state))` in the denominator. The pre-revision text was correct on this point, so the change is a regression, and the report's claim that the new formula "matches Fujimoto & Gu 2021" is wrong. (The scale-invariance argument in `review.md` Exercise 7 holds for either denominator, so only the paper fidelity is affected.) — Suggested fix: restore $\lambda = \alpha/(\frac1N\sum_i |Q(s_i,\mu_{\theta_{\text{old}}}(s_i))|)$ and describe the denominator as "the mean absolute Q-value of the current policy's actions".

3. `docs/chapter10_offline_rl/experiments.md` — "it controls the update step size of the current policy relative to the reference policy" — this sentence was left untouched while the two bullets under it were corrected, so the paragraph now contradicts itself and Chapter 14. $\beta$ is the weight of the KL penalty in $\max_\pi \mathbb{E}[r] - \beta\,\mathrm{KL}(\pi\|\pi_{\rm ref})$ (i.e. the inverse temperature of the implicit reward), not a step size; `docs/chapter14_dpo/metrics.md` says exactly that ("beta is the regularization strength controlling how far the policy is allowed to drift from the reference model … if beta is large the policy is heavily constrained"). The corrected bullet ("If β is too small: … the update steps are too big") still reads β as a step size. — Suggested fix: rewrite the lead-in as "it controls the strength of the KL anchor to the reference policy (equivalently, the temperature of the implicit reward)", and drop the "update steps are too big" phrasing from the β-too-small bullet.

4. `docs/chapter10_offline_rl/offline-data-distribution-shift.md` (§3.3) — "the target still has the step $\max_{a'} \pi(a'|s')$" — $\max_{a'}\pi(a'|s')$ is a maximum over a policy probability, which is not the Bellman backup; the intended statement is that AWAC's target still contains $\max_{a'} Q(s',a')$, which is exactly why OOD actions may be queried (and why AWAC is weaker than IQL). This is a pre-existing error inside the writer's own page that the revision did not fix. — Suggested fix: replace with "the target still has the step $\max_{a'} Q(s', a')$".

5. `docs/chapter10_offline_rl/review.md` (Exercise 9, solution code) — "wis_est = (rho * rew).sum() / rho.sum()" / "ess = rho.sum() ** 2 / (rho ** 2).sum()" — the exercise explicitly asks the reader to re-run with the logger pulling arm 1 only 5% of the time, and in that regime the given code divides by zero: with $N=50$ and $p=0.05$, the logger never pulls arm 1 with probability $0.95^{50}\approx 0.077$, so $\sum_i\rho_i=0$ and both `wis_est` and `ess` become `nan` (0/0). Running the snippet as printed for 200 seeds gives `nan` in ~9% of seeds, and the printed `IS mean/var`, `WIS mean/var` and `mean ESS` lines are all `nan`, so the stated "expected behavior" (mean ESS ≈ 2–3, WIS variance smaller) cannot be reproduced from the code as given. (Excluding the degenerate seeds the numbers are right: mean ESS = 2.76, median 3.) — Suggested fix: guard the division, e.g. `den = max(rho.sum(), 1e-12)` and skip/flag runs with `rho.sum() == 0`, and say in the expected behavior that ~8% of seeds have no arm-1 pull at all and must be dropped.

## Doubts

1. `docs/chapter10_offline_rl/offline-data-distribution-shift.md` (CQL snippet) — "q_next = self.critic1(s, a_next)   # [B, 1], policy actions" — in the same function `a_next = self.actor(s_next)`, so `a_next` is the policy's action at $s_{t+1}$, evaluated here at $s_t$. CQL(SAC) forms the logsumexp over actions drawn from $\pi(\cdot|s)$ at the *same* state, so the "OOD stand-in" set is really {random action at $s$, data action at $s$, policy action at $s_{t+1}$}. The regularizer's sign and shapes are right, but the comment mislabels what is being evaluated; consider `a_pi = self.actor(s)` instead.

2. `docs/chapter10_offline_rl/offline-data-distribution-shift.md` (CQL guarantee) — "the estimated policy value $\hat V^\pi(s)=\mathbb E_{a\sim\pi}[\hat Q(s,a)]$ sits below the true $V^\pi(s)$ on states covered by the data, so the policy's return is never overestimated on average" — the direction of the correction (expectation-under-$\pi$, not pointwise) is right, but the exact statement in Kumar et al. 2020 (Thm. 3.1/3.2) carries an $O(\varepsilon)$ slack and is stated under assumptions (exact minimization, expressivity of the Q class, coverage of the data) that the sentence silently drops; also worth checking whether the paper's bound is written for the optimal policy rather than "the policy being evaluated". Worth verifying the wording against the paper before shipping.

3. `docs/chapter10_offline_rl/offline-data-distribution-shift.md` (§2.5, new) — "Large action gaps — regions of the action space with no samples — are exactly where the logsumexp penalty of CQL or the expectile of IQL has to guess" — IQL never evaluates an out-of-dataset action (that is the whole point of the method, stated two sections earlier), so the expectile does not "guess" in the gap regions; only CQL's logsumexp does. Suggest restricting the sentence to CQL/BCQ-style methods.

4. `docs/chapter10_offline_rl/sequence-modeling.md` — the symbol $K$ now carries two meanings on the same page: the DT context length ("cut a history window of length K", `K=20` in the class) in §1, and the diffusion horizon ("the diffusion step (from 0 to $K$ …)", "iterate the reverse process over its $K$ diffusion steps") in §3, which the revision just introduced. The rename from $T$ to $K$ does avoid clashing with the trajectory length $T$, but it now collides with §1's $K$ inside one page. Consider $T_{\text{diff}}$ or $N_{\text{steps}}$.

5. `docs/chapter10_offline_rl/sequence-modeling.md` (inference pseudocode) — "target_return = 9000  # Roughly the expert-level score in the HalfCheetah environment" — the value is unsourced; the DT paper/code conditions on 3600 for the standard HalfCheetah medium tasks, and the expert-level number for HalfCheetah-expert is around 11k in the paper's figures, so 9000 is a plausible but unverified "roughly". Also, "the DT `act` now reads `history.rtg`, but the pseudocode's `TrajectoryBuffer` only ever stores `(state, action, reward)` (`history.append(state, action, reward)`) — the RTG column that the new code indexes is never written, and the required dtypes/shapes of `history` (`history.rtg` must be `[n,1]`, `history.actions` must be `[n,act_dim]`, and `history.actions` must exclude the current step for the three sequences to stay aligned) are nowhere specified. Please document the buffer contract or show it.

6. `docs/chapter10_offline_rl/experiments.md` (§5, new) — the worked example compares returns of *different* action sequences ($G_1=10$, $G_2=2$, $G_3=6$), which implicitly assumes the same state trajectory; the text then reads the WIS value 10 as "the return of the candidate's deterministic action sequence $(a_1,a_1)$", which only holds under that assumption. A one-line remark ("assume all three episodes start from the same state") would make the arithmetic self-consistent. Also "because $T$ noisy ratios multiply" uses $T$ (horizon) without defining it in §5, and $T$ already means Bellman-iteration count in 10.1.

7. `docs/chapter10_offline_rl/experiments.md` (§5.3, new) — the DR estimator is written with the *cumulative* weight $\rho_{1:t}$, while the standard doubly robust estimator of Jiang & Li (2016) uses the per-decision weight $\rho_t=\pi(a_t|s_t)/\mu(a_t|s_t)$. The cumulative version is still doubly robust (the telescoping identity $\mathbb E_\mu[\rho_{1:t}f]=\mathbb E_\pi[f]$ holds) but has a different variance profile; consider citing the per-decision form or noting the difference.

8. `docs/chapter10_offline_rl/experiments.md` — the section roadmap paragraph "In this section we connect the two fields. First we explain the deep link between DPO … then we map preference data … then we show how the sequence-modeling idea enters LLM reasoning search, and finally we point out what this analogy can explain and what it cannot replace" was not updated for the new §5, even though the Reading Guide gained an OPE bullet. Consider adding a clause for the new section.

9. `docs/chapter10_offline_rl/offline-data-distribution-shift.md` (§2.1, pre-existing) — "sample n candidate actions (say n=100)" — Fujimoto et al. 2019 (BCQ) Algorithm 1 uses $n=10$ sampled actions for the perturbed argmax (100 samples are used in the "BCQ 10% random" variant), so "say n=100" does not match the cited paper. Not touched by this revision, but it is in the writer's page.

10. `docs/chapter10_offline_rl/review.md` — the page uses the heading label "10.R", a convention that exists nowhere else in the book (no other chapter has a summary/exercise page) and that `scripts/fix-heading-numbers.mjs` cannot process (its regex only matches `text: 'N.M ...'`). The label will drift as soon as a real section number is assigned; also the front-matter `title: 10.R Summary and Exercises` duplicates the H1, which is fine for the other appendix pages that do the same.

## Verdict

The revision is technically strong where it matters most: the OPE section added to 10.3 is well-chosen, its estimators, ESS arithmetic and worked example are correct, the DPO-$\beta$ bullets were fixed in the right direction, the CQL snippet now runs, and the $\gamma$-decay number ($0.99^{100}\approx0.366$, ≈459 iterations to 1%) is right. The exercise solutions were checked by re-derivation (RTG, $\epsilon/(1-\gamma)$, expectile at $\tau=0.5$, IS/WIS/ESS, TD3+BC scale invariance, and both code exercises run and produce the stated numbers). The serious problems are consistency and fidelity: the rewritten `DecisionTransformer.act` no longer matches its own call site in the inference pseudocode (a guaranteed `TypeError`), the TD3+BC weight was "fixed" into a formula that contradicts Fujimoto & Gu (2021) — a regression on a point that was already right — and the DPO paragraph still asserts that $\beta$ controls the update step size, contradicting both the corrected bullets and Chapter 14. Two required repository steps were skipped entirely: the new `review.md` was never added to the VitePress sidebar, and the two chapter-10 items in `planning/content-review-notes.md` were not marked fixed. Fixing items 1–3 and 6–7 would make this revision mergeable; the remaining doubts are wording-level.
