# Review of ch04-lab

Scope: `git diff english-only...w/ch04-lab` (new `docs/chapter04_classical_methods/lab.md`, new `code/chapter04_classical_methods/` with 6 Python files + README + requirements.txt). The branch's own report `planning/reports/ch04-lab.md` does not exist on `w/ch04-lab`, so the scope had to be reconstructed from the diff. Every experiment was re-run locally with the repo `.venv` (gymnasium 1.4.0, numpy 2.5.4): `dp_oracle.py`, `mc_td_control.py` (10 seeds x 20 000 episodes x 4 algorithms), `cliffwalking.py` (10 seeds x 500 episodes x 2 algorithms), `ope_is.py` (100 trials x 2 000 episodes, plus a 500-trial re-run and a no-truncation control run), plus the unit tests and the smoke tests, and all DP arithmetic was re-derived from the exact `env.unwrapped.P` model.

## Errors

1. `docs/chapter04_classical_methods/lab.md` (page as a whole) / `docs/.vitepress/config.mjs` (untouched) — the new page is never registered in the hand-written sidebar: the Chapter 4 block of `config.mjs` still lists only 4.1, 4.2 and 4.3. AGENTS.md requires "Every navigable page must be listed there", so the lab is unreachable from the site ToC (it only reaches the sitemap, which `scripts/generate-sitemap.mjs` builds by scanning `docs/**/*.md`). The chosen number also hides the page from the heading tooling: `scripts/fix-heading-numbers.mjs` matches sidebar entries with `/text:\s*'(\d+)\.(\d+)\s([^']*)'/` and H1s with `/^#\s*(\d+)\.(\d+)\b/`, so neither `text: '4.L ...'` nor `# 4.L Lab: ...` is recognised, and `npm run fix:headings` cannot normalise the page. (The same defect was flagged for the sibling `ch04-text` branch's "4.R" page, so this is a known repo trap.) — Suggested fix: add `{ text: '4.4 Hands-on: Tabular Methods Against Exact Oracles', link: '/chapter04_classical_methods/lab' }` under "4. Classical RL Methods" and rename the front-matter title and the H1 to "4.4 Hands-on: Tabular Methods Against Exact Oracles" so the heading script can keep them in sync.

2. `docs/chapter04_classical_methods/lab.md` — "All numbers below come from the full run (`--seed 0`, CPU)." is immediately contradicted by the tables: Experiment 2 ships `| MC first-visit | RESULT | RESULT | RESULT |` … `| Q-learning | RESULT | RESULT | RESULT |` plus the marker `<!-- RESULTS-TODO: fill from control_summary.json -->`, and Experiment 4 ships "RESULT trials x RESULT behaviour episodes each" with `RESULT` in every cell of the estimator table. `code/chapter04_classical_methods/README.md` has the same defect (`<!-- TODO: fill from control_summary.json -->`, `<!-- TODO: fill from ope_summary.json -->`, and body cells `...`). The HTML comments are invisible when rendered, so a reader of the published page sees a table of the literal word "RESULT". — Suggested fix: paste the actual numbers from `control_summary.json` / `ope_summary.json` (I have recomputed them; they are listed in errors 3 and 5 below) and delete the TODO markers.

3. `docs/chapter04_classical_methods/lab.md` (Experiment 2) — "The learning-curve plot shows mean $\pm$ std over the 10 seeds: greedy-policy return rises toward the optimal $0.82$ success rate while the max-norm oracle error falls on a log scale." The shipped code does not do this. Running `mc_td_control.py --seed 0` (eps=0.1, alpha=0.1, gamma=1, 10 seeds x 20 000 episodes) gives: MC first-visit greedy return 0.140 +/- 0.118, SARSA 0.465 +/- 0.335, Expected SARSA 0.510 +/- 0.359, Q-learning 0.195 +/- 0.304; final max `||Q - Q*||` = 0.8516 / 0.7144 / 0.7344 / 0.5493; online last-10% = 0.0734 / 0.2717 / 0.2748 / 0.1257. Nothing reaches 0.82 and the oracle-error curves plateau (they fall from 0.94 to 0.55-0.85 over 20 000 episodes, they do not converge). Worse, for seeds 0 and 2 the greedy policy extracted from the learned Q has an _exact_ success probability of 0.000 (I evaluated the learned greedy map with DP policy evaluation): the over-estimated Q at states 0-3 makes the agent climb into the top row, where the greedy arrows form a closed loop, so it never reaches the goal. The lab's headline claim therefore cannot be published as written. — Suggested fix: either change the configuration until the claim is true (decaying epsilon, more episodes, a larger alpha, or gamma<1) or restate the result honestly ("with a constant eps=0.1 and alpha=0.1 the tables do not converge in 20 000 episodes; the greedy return plateaus around 0.2-0.5 and Q-learning's table is the only one that keeps approaching Q\*") — but then the "0.82 success rate" sentence must go.

4. `docs/chapter04_classical_methods/lab.md` (Experiment 2 + "What to Look For") — the max-norm error to $Q^\star$ is used as one shared yardstick for all four methods, and the bullet "The oracle error separates 'still learning' from 'unlucky' ... so a shrinking error means the table itself is converging" reads that error as a distance to the optimum. That is only meaningful for Q-learning. With a fixed eps=0.1 behaviour, SARSA, Expected SARSA and first-visit MC converge to $Q^{\epsilon\text{-greedy}}$, not to $Q^\star$. I evaluated that policy exactly with the DP code: $V^{\epsilon\text{-greedy}}(s_0)=0.417536$ (not 0.8235) and $\|Q^{\epsilon\text{-greedy}}-Q^\star\|_\infty = 0.5057$. So the on-policy curves have a floor of about 0.51 _by construction_, and their "oracle error" can never be read as a convergence measure; the observed 0.71-0.85 values are just that floor plus noise. This is also why the on-policy methods' _online_ returns (0.27) sit far below 0.82 while their greedy returns look reasonable. — Suggested fix: report `||Q - Q*||` only for Q-learning, and for the on-policy methods report `||Q - Q^{eps-greedy}||` (computable from the same DP code) or simply the online return; state explicitly in the text that the on-policy methods target $Q^{\epsilon\text{-greedy}}$, whose start value is 0.4175.

5. `docs/chapter04_classical_methods/lab.md` ("Importance weights collapse over long horizons") — "That is why ordinary IS is unbiased but jumps around (variance)". Ordinary IS is measurably _biased_ in the shipped configuration. `ope_is.py --seed 0` (100 trials x 2 000 episodes) gives OIS bias $-0.0513$; `--seed 7 --n-trials 500` gives bias $-0.0825$ with a standard error of $0.2441/\sqrt{500}=0.011$, i.e. about $-7.6$ standard errors, so the bias is 6-10% of the true $V^\pi(s_0)=0.823529$. The cause is the environment's time limit, not the estimator: gymnasium's `FrozenLake-v1` truncates every episode at 100 steps, 3.2% of behaviour episodes hit that cap, and `collect_dataset` stops accumulating at `done = terminated or truncated` without bootstrapping the missing tail (the _target_ policy is even longer-lived: mean episode length 44 steps, 10% of its trajectories are truncated). Control experiment: re-running the identical estimator with `max_episode_steps=100000` gives an OIS bias of $+0.0034$ (SE 0.056) and a WIS bias of $-0.0028$ — unbiased only without truncation. The lab's own "Bias" column (currently `RESULT`) would show this, and the README's sentence "Ordinary IS is approximately unbiased with large variance" has the same problem. — Suggested fix: bootstrap at truncation (add $\gamma V^\pi(s')$ from the DP oracle when `truncated` is true), or raise the time limit for this experiment, and then state the measured bias instead of asserting unbiasedness.

6. `docs/chapter04_classical_methods/lab.md` (Background) — "[4.3 Reward Function Design](./reward-design) — CliffWalking's cliff penalty of $-100$ versus $-1$ per step is a small case study in how reward magnitudes shape the learned path." `reward-design.md` never mentions CliffWalking (zero occurrences of "cliff" in the file) and never discusses a $-100$ cliff penalty; its reward-magnitude case studies are the three gridworld rules A/B/C, CartPole, the MuJoCo Humanoid/HalfCheetah/Ant/BipedalWalker reward terms, PBRS, Coast Runners and Minecraft. The cross-reference therefore points at material that does not exist in the target page. — Suggested fix: either add the CliffWalking $-100$-vs-$-1$ case study to 4.3 (it fits the "scale mismatch" pitfall already there), or point the bullet at something 4.3 actually contains (e.g. the Coast Runners / Goodhart section) and keep the CliffWalking discussion inside the lab.

7. `code/chapter04_classical_methods/README.md` — the table header `| Method | Final greedy return | Final max |Q-Q*| | Online (last 10%) |` contains unescaped pipes inside `|Q-Q*|`. Splitting on `|` gives 5 header cells ("Method", "Final greedy return", "Final max", "Q-Q*", "Online (last 10%)") against 4 cells in every body row, so the table does not render. — Suggested fix: escape the inner pipes (`\|Q-Q*\|`) or write the header as `Final max ‖Q − Q\*‖`.

8. `docs/chapter04_classical_methods/lab.md` (Experiment 1 table) — the row `| Policy iteration | 617 eval sweeps, 2 improvements | $6.56 \times 10^{-7}$ | 0.823506 |` and the value-iteration row both give $V^\star(s_0)=0.823506$, but running `dp_oracle.py` shows policy iteration returns 0.8235125 and value iteration 0.8235061 (they differ by the $1.12\times10^{-5}$ the text itself quotes). The PI cell is a copy of the VI value. — Suggested fix: write 0.823512 in the policy-iteration cell (or round both to 0.8235 and note that the difference is below the printed precision).

9. `docs/chapter04_classical_methods/lab.md` (Experiment 2 preamble) — "Four methods, epsilon-greedy behaviour ($\epsilon = 0.1$), $\alpha = 0.1$, 10 seeds $\times$ 20,000 episodes" lists a step size for Monte Carlo control, but `train_mc` never takes one: it applies the incremental sample mean `Q += (G - Q) / counts[s, a]`, and the module docstring itself says "No step size is needed: `1 / N` is the learning rate". Listing $\alpha=0.1$ for the MC row is wrong. — Suggested fix: say "alpha = 0.1 for the three TD methods; MC uses the incremental 1/N mean instead".

10. `code/chapter04_classical_methods/mc_td_control.py` (`run_episode_td`) and `code/chapter04_classical_methods/cliffwalking.py` (`run_cliff`) — SARSA's truncation branch bootstraps from the wrong action. In both loops `next_action` is forced to `0` whenever the episode ends, while `bootstrapped_done` is `False` for a truncation (the environment's time limit, or the 200-step cap in `cliffwalking.py`). The SARSA target therefore becomes `reward + gamma * Q[ns, 0]` — the value of the "up" action — instead of `reward + gamma * Q[ns, a'_behaviour]`, so the on-policy property of SARSA is broken exactly on the steps where the episode is cut short. (Q-learning and Expected SARSA are unaffected, since they use `max` and an expectation.) — Suggested fix: sample the next behaviour action whenever the update bootstraps, i.e. compute `next_action` before the `step_done` branch and only ignore it when `bootstrapped_done` is true.

11. `code/chapter04_classical_methods/common.py` (`load_model`) — the docstring says "Returns `(P, n_states, n_actions, terminals)`", but the function returns five values (it also returns `resolved_id`), and all five call sites unpack five. — Suggested fix: correct the docstring to `(P, n_states, n_actions, terminals, resolved_id)`.

## Doubts

1. Runtime estimates are several times too high. `code/chapter04_classical_methods/README.md` claims `dp_oracle.py` "< 5 s", `mc_td_control.py` "~7 min", `cliffwalking.py` "~25 s", `ope_is.py` "~4 min", and `lab.md` says "Full lab (about ten minutes on CPU)". Measured on this machine: 0.3 s / 110 s / 2.3 s / 33 s, i.e. about 2.5 minutes in total, and the pytest smoke run takes 2.5 s rather than "under ~60 s". Machine speed explains part of it, but a 4x gap on `mc_td_control.py` is worth re-measuring on the reference machine before publishing the table.

2. `docs/chapter04_classical_methods/lab.md` — "The top row of the SARSA map and the bottom row of the Q-learning map tell the story: SARSA travels high, Q-learning hugs the cliff." The bottom row of the Q-learning map is the cliff row `SCCCCCCCCCCG`, which carries no arrows at all; the cliff-hugging path is the row immediately above it (row 2: `>>>>>>>>>>>v`, i.e. the agent travels along the row directly above the cliff and then steps down into the goal). (The two maps themselves are byte-identical to what `render_path` prints for seed 0 — I diffed them — so only the description is off.)

3. `docs/chapter04_classical_methods/lab.md` (Extension Exercise 4) — the hint "at some point no episode in a batch matches the target at all, and weighted IS returns exactly 0" overstates the effect for the two epsilon values the exercise asks for. Measured over 20 batches of 2 000 episodes: at eps=0.3 no batch had all-zero weights (mean ESS fraction 0.0042, WIS mean 0.840), at eps=0.5 only 1 batch in 20 did (mean ESS 0.0011). All-zero batches only become typical around eps=0.7 (14/20). — Suggest rewording the hint, e.g. "as epsilon grows the ESS fraction collapses by two to three orders of magnitude and occasional batches contain no matching trajectory at all, in which case weighted IS returns exactly 0 (the guard in `weighted_is`)".

4. `docs/chapter04_classical_methods/lab.md` (Extension Exercise 1) — the hint "value iteration's error shrinks roughly geometrically" is loose for this model: the per-sweep error ratio is 0.933 at sweep 2, the error is still 8.235e-01 at sweeps 2-5, and the ratio is already 0.995 at sweep 6 and 0.989 at sweep 8, i.e. the decay rate is not a constant geometric factor. The second half of the hint is right: sweeps vs. theta are 40 (1e-2), 243 (1e-4), 431 (1e-6), 618 (1e-8), 806 (1e-10), 993 (1e-12), i.e. about 95-100 sweeps per decade, logarithmic in $1/\theta$.

5. `code/chapter04_classical_methods/mc_td_control.py` (`train_mc`) — Monte Carlo control treats a time-limit-truncated episode's partial return as if the episode had really ended (no bootstrap is possible in MC, but the episode also does not terminate), which biases the MC estimates slightly downward on FrozenLake; the TD methods in the same file handle the same event correctly (`bootstrapped_done = terminated and not truncated`). The lab does not mention this asymmetry between the four methods.

6. `code/chapter04_classical_methods/requirements.txt` introduces `gymnasium[toy-text]`, but the merged global summary `code/requirements.txt` was not updated with that extra (it lists only classic-control, box2d, mujoco and atari). The `toy-text` extra also pulls in pygame although FrozenLake and CliffWalking are never rendered in this lab.

7. `docs/chapter04_classical_methods/lab.md` (Experiment 3) — SARSA's greedy-policy return is $-53.60 \pm 73.20$ over 10 seeds, i.e. the "safer path" greedy policy is not stable across seeds (some seeds are far from the optimal $-13$). The numbers are exactly reproducible (I re-ran the script), but the tidy narrative "SARSA ... prefers the safer path ... better behaviour, worse final greedy policy" hides a very large spread; a sentence about the seed-to-seed variance would make the lesson sharper and more honest.

8. `planning/reports/ch04-lab.md` (the writer's own report, referenced in the task) does not exist on `w/ch04-lab` — the `planning/` tree contains only `content-review-notes.md` and the outline files. I could therefore not check the writer's stated scope, claimed measurements, or self-reported limitations.

## Verdict

The engineering behind this lab is careful and, where it can be checked, exactly right: I re-ran every script and the DP oracle reproduces the published numbers to the digit (40 policy-evaluation sweeps, 617 evaluation sweeps and 2 improvements for policy iteration with residual 6.56e-7, 431 value-iteration sweeps with residual 9.61e-7, agreement 1.12e-5, $V^\star(s_0)=14/17$), the CliffWalking experiment reproduces the table verbatim (SARSA $-35.90\pm67.94$ / greedy $-53.60\pm73.20$ / 0.102 falls; Q-learning $-56.95\pm90.65$ / greedy $-13.00\pm0.00$ / 0.365 falls, a 3.6x fall ratio), the printed greedy maps are byte-identical to the code's output, the OPE machinery is a correct importance-sampling estimator, the unit-test arithmetic is right, and the tests pass. The page nevertheless is not publishable as it stands. Four things block it: the page is missing from the sidebar (so it is unreachable and its "4.L" number is invisible to the heading tooling); the Experiment 2 and Experiment 4 tables still contain the literal word "RESULT"; the headline claim of Experiment 2 ("greedy-policy return rises toward the optimal 0.82 success rate while the max-norm oracle error falls") is contradicted by the code's own output, which plateaus at 0.14-0.51 success and an oracle error of 0.55-0.85, with Q-learning's greedy policy having an exact success probability of 0.000 on two of ten seeds; and the "oracle error" is used as a shared yardstick even though the three on-policy methods provably converge to $Q^{\epsilon\text{-greedy}}$, whose distance to $Q^\star$ is 0.5057, so their curves cannot fall to zero. The fourth block is in Experiment 4: ordinary IS is asserted to be unbiased but is measurably biased downward ($-0.05$ to $-0.08$, about $-7.6$ standard errors) because FrozenLake's 100-step truncation is not bootstrapped — with the truncation removed the same estimator is unbiased ($+0.003$). Fix the sidebar entry, fill the tables from the scripts, correct the two convergence claims and the unbiasedness claim, and the lab becomes a genuinely good addition to Chapter 4.
