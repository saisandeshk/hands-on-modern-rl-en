# Review of ch09-text

Scope: `git diff english-only...w/ch09-text` (2 changed Chapter 9 pages + new `docs/chapter09_continuous_control/review.md` + a stray `MUJOCO_LOG.TXT` + two unrelated binary files). Every number below was recomputed with `.venv/bin/python`; the two changed equations ($\arg\max\to\arg\min$ for $\alpha$, $V^\pi\to V^*$ soft value), the three corrected compounding-error sums, and all eight exercise solutions were re-derived by hand and checked against `code/chapter09_continuous_control/ppo_td3_sac_comparison.py`. Note: the writer's report `planning/reports/ch09-text.md` does **not** exist on the branch (`planning/` contains only `content-review-notes.md` and the outline files), so this review is based on the diff alone.

## Errors

1. `docs/chapter09_continuous_control/td3-sac.md` (line 285, new "Bounded Actions: Tanh Squashing") — "$\log \pi(a \mid s) = \log \mu(u \mid s) - \sum_i \log(1 - \tanh^2(u_i))$" with $a = a_{\max}\tanh(u)$ — the change-of-variables term for the action **scaling** is missing. The density of the executed action is $p_a(a) = p_u(u)\,\bigl|du/da\bigr| = p_u(u)\big/\bigl(a_{\max}(1-\tanh^2 u)\bigr)$, so the correct formula is $\log\pi(a|s) = \log\mu(u|s) - \sum_i\log a_{\max} - \sum_i\log(1-\tanh^2(u_i))$. The code snippet two lines below (`actions = self.action_max * torch.tanh(u)`) keeps the $a_{\max}$ factor but the correction does not, so for $a_{\max}\neq1$ the reported entropy is off by $d\log a_{\max}$ (for $a_{\max}=2$, $d=6$: $4.16$ nats), which also breaks the target-entropy matching ($\mathcal{H}_0=-|\mathcal{A}|$) that the temperature loss relies on. The same wrong formula is repeated in `review.md` line 30 ("Squashed log-probability"). The worked numbers on line 299 are fine only because that example sets $a_{\max}=1$ (checked: $\tanh 0.5=0.4621$, $\log\mathcal N(0.5;0,0.25)=-0.7258$, $-\log(1-0.2136)=+0.2402$, sum $=-0.4856$ — all correct). — Suggested fix: write $\log\pi(a|s)=\log\mu(u|s)-\sum_i\log a_{\max}-\sum_i\log(1-\tanh^2(u_i))$, and note that for the usual MuJoCo bounds ($[-1,1]$) the $\log a_{\max}$ term vanishes.

2. `docs/chapter09_continuous_control/td3-sac.md` (lines 272–299 vs. lines 195–198, 219–231, 255–262, 359) — the new subsection says "Every $\log \pi$ in the actor loss and the temperature loss must use this corrected value", but the page's own implementation still defines a *different*, unsquashed SAC: line 198 states "$a \sim \mathcal{N}(\mu_\theta(s),\sigma_\theta^2(s))$", line 217 defines the reparameterized action as "$a = \mu_\theta(s) + \sigma_\theta(s)\odot\epsilon$" (no $\tanh$), the actor-loss snippet (lines 224–231) does `actions = dist.rsample()` + `dist.log_prob(actions)` with no squashing, the temperature snippet (lines 259–260) does the same, and the "Soft Q Update" bonus box (line 359) uses the unsquashed $-\alpha\log\pi_\theta(\tilde a'|s')$. After this change the page teaches two mutually exclusive SAC policies and a reader who copies the earlier snippets gets exactly the bug the new section warns about. — Suggested fix: rewrite the "Stochastic Policy and the Reparameterization Trick" section and both code snippets to the squashed policy ($u\sim\mathcal N$, $a=a_{\max}\tanh(u)$, corrected $\log\pi$), and add the correction to the soft-Q target; if the unsquashed snippets are kept for simplicity, label them explicitly as "simplified (no action squashing)" and cross-reference the new subsection.

3. `docs/chapter09_continuous_control/model-based.md` (line 306, new "Pessimism, Decision-Relevant Error, and Distribution Shift") — "PETS achieves a similar effect implicitly: trajectories that pass through high-uncertainty regions vary wildly across ensemble members, so few of them survive elite selection." — this describes a mechanism PETS does not have, and the direction is backwards. In PETS's TS1 each trajectory is rolled out with **one** randomly chosen ensemble member and the CEM elite set is selected on the returns computed from those trajectories; there is no within-trajectory comparison across members, so an uncertain trajectory is not filtered out — if anything it can draw a lucky high return from one member and be selected, which is precisely the model-exploitation failure the paragraph is warning about. PETS actually handles epistemic uncertainty through (i) TS1 (one model per trajectory, so each rollout is a coherent alternative world rather than an unrealistic "averaged" dynamics) and (ii) the uncertainty value function at the end of the planning horizon ($V(s)=\mathbb{E}_i V_i(s)-\beta\,\mathrm{std}_i V_i(s)$). — Suggested fix: "PETS gets a related effect by different means: each trajectory is rolled out with a single ensemble member (TS1), so the elite set contains whole alternative futures rather than averaged dynamics, and PETS additionally uses an uncertainty value function at the horizon end, $V(s)=\mathbb{E}_iV_i(s)-\beta\,\mathrm{std}_iV_i(s)$."

4. `docs/chapter09_continuous_control/review.md` (new page; `docs/.vitepress/config.mjs`) — the page is an orphan: the chapter-9 block of the sidebar still lists only 9.1–9.4, no page links to `review.md`, and the frontmatter/H1 use a non-numeric minor number "9.R" that `scripts/fix-heading-numbers.mjs` cannot parse (its regex is `text:\s*'(\d+)\.(\d+)\s…'`), so `npm run fix:headings` will never validate or renumber it. 6. `docs/chapter09_continuous_control/review.md` (line 106, Exercise 7 solution) — "TD3 and SAC store every transition in a replay buffer ($100{,}000$ capacity here) and re-update from it hundreds of thousands of times ($256$-sample batches every step)" — the counts do not match the chapter's own script. `code/chapter09_continuous_control/ppo_td3_sac_comparison.py` sets `train_freq=1, gradient_steps=1`, so the 50,000-step run performs exactly **50,000 gradient updates** (one per environment step), each drawing a 256-sample batch, i.e. $50{,}000\times256=12.8$ million samples drawn from the buffer (each stored transition is reused ~256 times on average). Neither "hundreds of thousands of times" (updates) nor "hundreds of thousands" (samples) is right. — Suggested fix: "re-use from it 50,000 times (one gradient update per environment step), each drawing a 256-sample batch — about 12.8M samples in total, so every stored transition is seen ~256 times".

## Doubts

1. `docs/chapter09_continuous_control/review.md` (line 127, Exercise 8 solution) — "With a fixed $0.2$, the entropy bonus permanently outweighs small reward differences late in training, so the policy stays overly diffuse, collects lower returns, and plateaus below the auto-tuned run." The stated mechanism does not fit Pendulum-v1, whose per-step reward is large (≈ −16), so a 0.2 entropy bonus does not "outweigh small reward differences"; in practice SB3's SAC with a fixed `ent_coef=0.2` still reaches near-optimal returns on Pendulum. Also the exercise asks to "log `train/entropy_coef` over time", but the sketch only prints `model.logger.name_to_value.get("train/entropy_coef")` after `learn()`, i.e. the last logged value, so it cannot produce the time series the exercise asks about (a `callback`/`logger.dump()` would be needed). — Suggest rewording to a hypothesis to be tested ("the fixed run keeps a non-zero entropy bonus throughout; compare the two return curves over several seeds") and using a callback to log the series.

2. `docs/chapter09_continuous_control/review.md` (line 106, Exercise 7 solution) — "the off-policy methods (SAC, TD3) clearly lead PPO — for example a run giving roughly SAC ≈ TD3 > PPO by a wide margin, with SAC usually marginally ahead of TD3" is plausible for HalfCheetah at 50k steps but is not backed by anything in the repository (no run logs, no committed figure), and the script falls back to **Pendulum-v1** when MuJoCo is missing — where PPO is comparatively much stronger, so the quoted "typical outcome" does not describe what most readers will actually see. — Suggest qualifying the numbers with the environment and the fallback.

3. `docs/chapter09_continuous_control/td3-sac.md` (line 315, changed) — "on environments such as HalfCheetah it reaches scores around 12000 after a million steps" — this is consistent with the page's own sketch and with published SAC curves at 1M steps (roughly 11k–12.5k), and it is a genuine improvement over the previous "above 15000"; but the chapter's own script (`code/chapter09_continuous_control/sac_halfcheetah.py`) trains for only 100k steps, so the figure cannot be reproduced from the repo and "around 12000" is stated more precisely than the repo supports.

4. `docs/chapter09_continuous_control/review.md` (line 68, Exercise 3 solution) — "So errors exceed unit scale after just 26 steps — the quantitative reason MBPO resets to a real state every 5 steps." The arithmetic is right ($1.1^{25}\Rightarrow0.983$, $1.1^{26}\Rightarrow1.092$), but the causal link is invented: crossing the unit scale at $T=26$ does not justify the specific choice of 5, and MBPO's rollout length is chosen empirically and adapted over training (as the chapter itself says two paragraphs earlier). — Suggest "which is the quantitative reason to keep model rollouts short (MBPO uses 5)".

5. `docs/chapter09_continuous_control/model-based.md` (line 308, new) — "MuZero's implicit model … trains the hidden dynamics only to predict rewards, values, and policies" — the substance is right (no observation reconstruction, no pixel loss), but strictly MuZero's dynamics function $g$ predicts the reward and the next hidden state, while a separate prediction function $f$ outputs policy and value, and the policy target is the MCTS visit distribution rather than a model prediction. The attribution of all three targets to "the hidden dynamics" is loose. — Suggest "trains the model only on decision-relevant targets: reward (dynamics function) and policy and value (prediction function)".

## Verdict

The revision is technically strong where it re-derives numbers: both compounding-error sums are now correct ($1163.909\epsilon$ and $170.481\epsilon$, matching my recomputation), the broken MBPO reset loop was rewritten into a correct "sample a real state, roll 5 steps, stop" loop, and two real formula bugs were fixed — the temperature objective must be **minimized** ($\arg\max\to\arg\min$, cf. Haarnoja et al. 2018, Eq. 17) and the soft value closed form belongs to the **optimal** policy ($V^\pi\to V^*$). All the hand-computable exercise solutions check out numerically (Exercise 3: 1163.9, 23.3, 25.16, 0.983/1.092; Exercise 4: PUCT(A)=0.7684 vs PUCT(B)=0.7714; Exercise 6: −0.7616, −1.4189, +0.8676, −0.5514; the numeric paragraph in §9.2: 0.4621, −0.7258, +0.2402, −0.4856), and the DDPG/DPG/twin-Q key equations match §9.1–§9.2. The main problems are in the *new* material: the tanh-squashing subsection states a log-density formula that drops the $\log a_{\max}$ Jacobian term while its own code keeps the scale factor, and it directly contradicts the unsquashed policy and code that the same page teaches above it; the PETS sentence about uncertain trajectories being filtered out by elite selection describes a mechanism PETS does not have (and gets the direction wrong); the new summary/exercise page is an orphan (not in the sidebar, non-parsable "9.R" label) so the exercises cannot be reached; the fixed errors were not marked in `planning/content-review-notes.md` as the repo requires; and two numeric statements in the Exercise 7 solution contradict the chapter's own figure and script. Housekeeping: the branch also commits a stray `MUJOCO_LOG.TXT` at the repository root and re-commits two unrelated binaries (`docs/chapter07_actor_critic/images/sac-real-robot.gif`, `docs/preface/brief-history/images/backgammon.jpg`) that belong to other chapters; and the writer's report `planning/reports/ch09-text.md` is missing from the branch entirely.
