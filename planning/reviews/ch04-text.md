## Errors

1. `docs/chapter04_classical_methods/dp-mc-td.md` (new section "From Evaluation to Control") — "the Bellman operators behind these sweeps are $\gamma$-contractions in the max norm: each sweep shrinks the distance to the fixed point $V^\pi$ by a factor of roughly $\gamma$" — false for the corridor the whole chapter runs on, because that corridor uses $\gamma=1$. The policy-evaluation operator is $V_{k+1}=AV_k+c$ with $A=\begin{pmatrix}0.2&0.8\\0.2&0\end{pmatrix}$, so $\|A\|_\infty=\max_i\sum_j|A_{ij}|=1.0$ (row sums $1.0$ and $0.2$): at $\gamma=1$ the operator is _not_ a contraction, and the greedy/optimality operator has the same $\infty$-norm $1$. The actual decay factor for this corridor is the dominant eigenvalue of $A$, $\lambda=0.51231$ (eigenvalues $0.51231$, $-0.31231$) — a number the chapter itself supplies in the new `review.md` Exercise 7 ("dominant error eigenvalue about $0.51$ per sweep"), so "roughly $\gamma$" (= 1 here) contradicts the chapter's own figure. The same wrong claim is repeated in the new summary bullet 6 ("The Bellman operators behind these sweeps are $\gamma$-contractions, so iterates converge to a unique fixed point") and in `review.md` Common Pitfalls 6 ("Values converge geometrically (contraction by $\gamma$ per sweep)"). Convergence here is real, but it comes from the absorbing walk (finite expected hitting time), not from a $\gamma$-contraction. — Suggested fix: state the theorem with its hypothesis ("for $\gamma<1$ the Bellman expectation/optimality operators are $\gamma$-contractions in the max norm, so the iterates converge geometrically to their unique fixed point"), then add the $\gamma=1$ case explicitly for this corridor ("with $\gamma=1$ the operator is not a strict contraction; here the sweep still contracts because the induced chain is absorbing — the observed factor is the dominant eigenvalue $0.51$"), and adjust bullet 6 and Common Pitfalls 6 accordingly.

2. `docs/chapter04_classical_methods/dp-mc-td.md` (Monte Carlo section, pre-existing but in the writer's scope; the writer's report claims every numeric example was recomputed) — "It traverses the trajectory backward, accumulating returns from each visit to the terminal state", followed by the update table ending at $V(S)=-3.125$, $V(M)=-1.5$ — the sentence and the table disagree. The table's "Old value" column is only reproducible if the updates are applied in _forward_ visit order (1st $S$, 2nd $S$, 1st $M$, 3rd $S$, 2nd $M$): $-3.5$, $-4.25$, $-2$, $-3.125$, $-1.5$. With the backward traversal the text actually describes, the update sequence is 2nd $M$ ($-1$, old $0\rightarrow-0.5$), 3rd $S$ ($-2$, old $0\rightarrow-1$), 1st $M$ ($-4$, old $-0.5\rightarrow-2.25$), 2nd $S$ ($-5$, old $-1\rightarrow-3$), 1st $S$ ($-7$, old $-3\rightarrow-5$), i.e. $V(S)=-5$, $V(M)=-2.25$ (verified by execution). Because $\alpha=0.5$ is not $1/N$, the final table depends on the update order, so the reader cannot get the printed numbers while following the stated algorithm. — Suggested fix: either reorder the table rows to the backward traversal and recompute the "Old value"/"New value" columns, or reword to "returns are accumulated backward from the terminal state, and the updates are applied in the order the visits occurred (the table below)" and note that the final values depend on the order because $\alpha=0.5\neq1/N$.

3. `docs/chapter04_classical_methods/algorithm-taxonomy.md` (new "Correcting the Mismatch: Importance Sampling" subsection) — "Actions the target favors count extra, actions it dislikes count less, and the weighted average is unbiased for the target expectation" — two paragraphs later the same subsection says "The weighted (self-normalized) estimator divides by the sum of the weights ... which is biased (the denominator is random)". The word "weighted" therefore denotes the unbiased estimator in one sentence and the biased one in the next, so the unbiasedness claim reads as false to any reader who takes the later definition. Only the _ordinary_ estimator $\hat V_{\rm ord}=\frac1n\sum_i\rho_iG_i$ is unbiased; the self-normalized one is not. (The section's numbers are otherwise right: $\rho_{\rm right}=0.8/0.5=1.6$, $\rho_{\rm left}=0.2/0.5=0.4$, ESS $=16/4.72\approx3.39$.) — Suggested fix: write "the ordinary, ratio-weighted average $\frac1n\sum_i\rho_iG_i$ is unbiased for $\mathbb E_\pi[G]$" here, and keep "weighted (self-normalized)" exclusively for the biased estimator.

4. `docs/chapter04_classical_methods/algorithm-taxonomy.md` ("Making Peace with Reality") — "PPO's clipping is one form of control, FP16 is another, and R3 routing replay is yet another" — the writer's edit replaced the unverifiable method name in the fix list ("R3 (Rollout Routing Replay) replays the inference routing distribution during training" → "Routing consistency: ... replaying the inference routing distribution during training"), but the same paragraph still names "R3 routing replay". The unsupported method name the edit was meant to remove survives, and the page now describes one and the same fix under two different names. — Suggested fix: change the remaining mention to "routing replay" (or "replaying the inference routing distribution"), matching the softened bullet.

5. `docs/chapter04_classical_methods/dp-mc-td.md` (new "Tabular Control" section, Expected SARSA) — "when $\pi$ is set to the greedy policy it coincides with Q-learning while still smoothing the target" — self-contradictory. With a deterministic greedy $\pi$, $\sum_{a'}\pi(a'\mid S_{t+1})Q(S_{t+1},a')=\max_{a'}Q(S_{t+1},a')$ exactly, so the Expected-SARSA target is _identical_ to the Q-learning target and nothing is smoothed. The smoothing property of Expected SARSA only exists for a stochastic $\pi$ (e.g. $\epsilon$-greedy); the chapter's own summary bullet 8 states this correctly ("matching Q-learning when $\pi$ is greedy"). — Suggested fix: "when $\pi$ is the greedy policy the two updates are exactly the same (the expectation over a point mass is the max), so no smoothing remains; smoothing appears only for a stochastic $\pi$".

## Doubts

1. `docs/chapter04_classical_methods/reward-design.md` — "use a large model (6B parameters) as the 'gold reward' and treat it as $R^*$ (the true preference), and use smaller models as proxy reward models for RL optimization" — in Gao, Schulman & Hilton, _Scaling Laws for Reward Model Overoptimization_ (ICML 2023), the roles I recall are the opposite: the 6B model is a _proxy_ reward model and the _gold_ reward model is a much larger one (175B). The figure in this very chapter (`images/reward-overoptimization-gao-rl.png`, captioned "Source: Gao et al. (2023)") should settle it, but I could not check the paper offline. The writer corrected the footnote year but not this sentence. — Please verify against the paper; if 6B is the proxy, the sentence has the two roles swapped.

5. `docs/chapter04_classical_methods/dp-mc-td.md` (new "Tabular Control" section) — "Q-learning ... pays with over-optimism during learning: the max operator propagates whatever exploratory danger the behavior policy encountered as if it never happened" — the technical term "optimism bias" in Q-learning comes from maximizing over _noisy value estimates_ ($\max_a\hat Q$ is biased upward), not from the target "ignoring" exploratory actions; the cliff-walk effect the sentence describes is the opposite direction (the greedy target omits the exploratory cost, so the risky optimal path looks attractive). As written the mechanism and the term are mixed. — Suggest: "the max over estimated values is upward biased (optimism), and because the target never charges for the exploratory step, the risky optimal path looks better than it is".

## Verdict

The revision is technically strong: I re-derived every new formula (policy improvement $Q(S,\mathrm R)=-2.875$ vs $Q(S,\mathrm L)=-5.375$; value iteration $(-1,-1)\to(-2,-1)$ hitting $V^*$ in two sweeps; $\lambda$-return weights $(1-\lambda)\lambda^{n-1}$; accumulating-trace update $z(s)\leftarrow\gamma\lambda z(s)+\mathbf 1\{s=S_t\}$; the three tabular control updates; ordinary vs. weighted IS and ESS $=3.39$) and every number checks out. All eight exercise solutions in the new `review.md` are correct as written: Exercise 3's fixed point $V(S)=-3.375$, $V(M)=-1.875$ is right; Exercise 4's MC/TD tables are right; Exercise 6's PBRS telescoping is right; Exercise 7 really does stop after 23 sweeps at $\theta=10^{-6}$ with $V(S)=-3.37499918$, $V(M)=-1.87499968$; Exercise 8's Q-learning run does converge to the greedy $(R,R)$ with values $(-2,-1)$ and the SARSA comparison is right because $\epsilon$-greedy with $\epsilon=0.2$ on two actions _is_ the chapter's $(0.8,0.2)$ policy, worth $(-3.375,-1.875)$. The most important defect is the new contraction argument: the chapter's corridor has $\gamma=1$, so "the Bellman operators ... are $\gamma$-contractions ... by a factor of roughly $\gamma$" is false there and contradicts the $0.51$ factor the same branch puts in Exercise 7; it is repeated in the new summary bullet and in `review.md` Common Pitfalls 6. Second is the pre-existing MC worked example, whose printed table ("traverses the trajectory backward") contradicts the update order the numbers actually encode (backward order gives $V(S)=-5$, $V(M)=-2.25$). Third, the writer's own softening of the unverifiable "R3"/44 %/MinPRO claims was incomplete (the name survives two paragraphs later) and the new IS subsection calls the estimator "the weighted average" two sentences before defining the "weighted" estimator as biased. Two smaller items: the Expected SARSA sentence claims Q-learning coincidence "while still smoothing the target" (with greedy $\pi$ the expectation _is_ the max, so nothing is smoothed), and the new page is not in the sidebar, with a "4.R" number the heading tooling cannot see. Fix those and register the page, and the branch is in good shape.
