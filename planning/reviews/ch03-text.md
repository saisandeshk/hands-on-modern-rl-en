## Errors

1. `docs/chapter03_value_functions/value-q.md` — "the learned $Q$ values are about: up $-4.8$, right $-4.7$, down $-4.7$, left $-4.9$. This indicates that ... 'right' and 'down' are both better than 'up' and 'left', **which matches the optimal values** ($-4.69$ for the two good moves that stay inside the grid, about $-5.22$ for the two moves that bump into the wall)" — the learned wall-bump entries do **not** match the optimal ones, and the sentence claims a match that the numbers contradict. On this grid ($-1$ per step, $\gamma=0.9$, goal $(3,3)$, start $(0,0)$), $V^*(0,0)=-(1-0.9^6)/0.1=-4.68559$, so $Q^*(0,0,\text{up})=Q^*(0,0,\text{left})=-1+0.9\,V^*(0,0)=-5.21703\approx-5.22$. The run reported in the same block gives up $=-4.797$ and left $=-4.919$, i.e. **over**-estimates of the optimum by $0.30$ and $0.42$ (the classic maximization bias of Q-learning with an $\varepsilon$-greedy behaviour policy: the wall-bump entry is its own bootstrap target, so it feeds back upward). Only right/down ($-4.686$) coincide with the optimum. The page also contradicts itself with `review.md` Exercise 6, which says wall-bumping moves are "about $-4.8$ to $-4.9$" (i.e. it uses the learned, not the optimal, numbers) — the two chapters of the same branch quote two different "wall-bump" values without saying which is which. — Suggested fix: state that the learned *ordering* is right/down > up/left, that the two optimal moves match the exact optimum ($-4.686\approx-4.69$), and that the two rarely-updated wall-bump entries are still over-estimates ($-4.80$ / $-4.92$ versus the exact $-5.22$) because the run has not converged on them; delete the word "matches" for the wall bumps.

The conclusion ($\boldsymbol{I}-\gamma\boldsymbol{P}_\pi$ invertible for $\gamma<1$) is correct, but the justification as written is not. — Suggested fix: "because $\rho(\boldsymbol{P}_\pi)=1$, so $\rho(\gamma\boldsymbol{P}_\pi)\le\gamma<1$ and $\boldsymbol{I}-\gamma\boldsymbol{P}_\pi$ is invertible" (or "eigenvalues lie in the closed unit disk").

## Doubts

1. `docs/chapter03_value_functions/value-bellman.md` (new subsection) — "the greedy policy often stabilizes several sweeps before the values have fully converged, which is why policy iteration can stop updating values early." The premise is weak in the chapter's own example: in the 4x4 grid, the greedy policy derived from $V_k$ changes at *every* sweep $k=0,\dots,4$ and only becomes stable at $V_5$, one or two sweeps before the values converge at $V_6$/$V_7$ (I recomputed `optimal_actions` for every sweep). The conclusion is also not what standard policy iteration does: S&B's policy iteration evaluates the policy to convergence and stops when the policy is unchanged; stopping the value updates early is only safe in the specialised "policy iteration with early stopping" (Puterman) variant. — Consider rephrasing to "the greedy policy usually settles a few sweeps before the values do, so in practice you often already know the policy while the values are still moving", and drop the policy-iteration clause unless it is spelled out.

2. `docs/chapter03_value_functions/value-q.md` — after the (correct) fix, the page says "The shortest safe path from S to G avoids the cliff: one step up, eleven steps across, and one step back down, for 13 steps in total", but a few paragraphs later it still says "The resulting policy follows the shortest path **beside the cliff**". In the corrected geometry the optimal path runs along the *top* row, above the cliff, not beside it; "beside the cliff" invites the old 11-step bottom-row reading. — Consider "along the top row, one cell above the cliff".

3. `docs/chapter03_value_functions/value-experiment.md` — the sidebar entry is "3.3 Hands-on: Value Function Experiments" while the page H1 and the new front-matter title are "3.3 Hands-on: Value Iteration and Q-Learning". `npm run fix:headings` will not reconcile them (the script only rewrites an H1 when the *number* differs, and 3.3 = 3.3), so the sidebar text and the page title will keep disagreeing. The writer flagged this as an open issue; it still needs a decision before merge.

4. Repository convention — AGENTS.md: "When fixing a factual error, record it (and the fix) in `planning/content-review-notes.md`." This branch fixed three genuine factual errors (the $1.998698$ slot-machine output, the 11-step CliffWalking path, the stale 4x4 Q-learning output block) but `planning/content-review-notes.md` was not touched at all (the report's "Technical fixes" box says "(none recorded)"). — Suggest adding a short entry for these three fixes so the notes file stays the single record of corrected errors.

5. `docs/chapter03_value_functions/review.md` (Exercise 8(b)) — "The terminal reward is already collected on entry (goal $+1$, trap $-1$), and terminal states are absorbing with value $0$." This matches the code (`transition` returns the reward on entry, `action_value` returns the bare reward when `done`), but the exercise asks the reader to "explain in one paragraph why `action_value` must return the bare reward when `done` is true" — the more precise reason is that the *terminal state has no successor*, so there is nothing to bootstrap; the reward is on the transition, not on the state. As written a reader could come away thinking the reward belongs to the terminal state. — Consider adding "the terminal state has no successor state, so there is no $V(s')$ to bootstrap".

Fixing those six items — plus the loose policy-iteration sentence, the stale "beside the cliff" phrasing, the 3.3 sidebar title and the missing `content-review-notes.md` entries — would make this branch solid.
